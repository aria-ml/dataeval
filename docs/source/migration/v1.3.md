# Migrating from v1.2 to v1.3

v1.3 adds experimental blur statistics to {func}`.image_stats` and {func}`.video_stats`, spatial statistics that compare
a box with its neighbors, context statistics that read the intensity around a box and how far the box stands from it, a
saturation statistic that counts the values at a clipping endpoint, experimental color statistics measured from channels
you declare are sRGB, noise statistics estimated from the pixels alone, experimental arguments that let
{class}`.Duplicates` search videos with long static stretches for shared segments, an experimental {func}`.frame_stats`
that measures the time between frames and exact repeats, two new columns of {func}`.track_stats`, the longest gap and
the net heading of a track, a `track_ids` property of {class}`.DetectionCrops` that gives the track of each crop, an
experimental {func}`.track_steps` that measures the step each detection takes from where its track was last seen, an
experimental {func}`.track_path_stats` that measures how far, and in which direction, the embeddings of each track
travel, an experimental `record_reads` option on {class}`.View` that lets {class}`.Metadata`
reuse what an earlier pass read, an experimental {func}`.set_load_threads` that loads dataset items in several threads
wherever DataEval reads a whole dataset, an experimental {meth}`.Embeddings.compute_multi` that computes several
extractors' embeddings from one read of a dataset, an experimental {class}`.TorchLayers` that reads several layers of
one torch model in one forward pass for it, an experimental {func}`.noise_pca` that estimates the noise of an image from
its patches, and object detection AP requirements on one class in the experimental {class}`.Feasibility`. It also makes
{func}`.image_stats` refuse boxes that are not four numbers, image readers refuse an item that holds more than one
image, and {class}`.Metadata`, {func}`.build_tracks` and {func}`.track_stats` refuse a track that cannot be stepped
through, {class}`.Metadata` keeps box coordinates at 64-bit precision, and {class}`.Embeddings` stores rows too large
for memory in a `.npy` file that `np.load` reads. {func}`.ego_stats` also refuses some pairs it trusted before. This
page lists what that means for existing code.

## Blur statistics

{class}`.ImageStats` has two new flags, `VISUAL_BLUR_EDGE_WIDTH` and `VISUAL_BLUR_EDGE_DIRECTIONALITY`, in the new group
`ImageStats.BLUR`. They add the columns `blur_edge_width` and `blur_edge_directionality`, and
`background_blur_edge_width` when `per_background=True`, which is the factor `unit_background_blur_edge_width` on a
{class}`.Metadata`, so `ImageStats.ALL` with `per_background=True` returns one more column, and one for each channel
group. {class}`.VideoStats` has one new flag, `BLUR_EDGE_WIDTH`, in the new group `VideoStats.BLUR`. It adds the column
`blur_edge_width_median`, and {func}`.video_stats` has a new keyword, `blur_samples`. See [Blur
statistics](../concepts/BlurStatistics.md) for what the values mean and what they cannot tell you.

```python
from dataeval.core import image_stats
from dataeval.flags import ImageStats

stats = image_stats(images, stats=ImageStats.BLUR)
```

`ImageStats.ALL` now includes the blur flags, and `VISUAL`, `VISUAL_BASIC` and `NO_HASH` do not. The default of
{func}`.image_stats` is what `ALL` was in v1.2 and the new `saturated_fraction` column (see the [saturation
statistic](#saturation-statistic)), so a call that passes no `stats` returns what it returned in v1.2 with that one
column added. A request for `ALL`, or for a complement such as `~ImageStats.HASH`, now measures blur. It costs much more
than `sharpness`: on one machine a 3840x2160 frame took over a second, and nothing caps the size of an image. `ALL`
holds every statistic of a release, the [spatial](#spatial-statistics), [context](#context-statistics),
[color](#color-statistics) and [noise](#noise-statistics) statistics too, so a later release can add to it again. A
per-target request for `ALL` on a dataset now reads the dataset's labels, since two of the spatial statistics compare
classes, so it can raise on malformed labels where v1.2 never read them.
{class}`.Outliers` with `flags=ImageStats.ALL` now judges the blur statistics too. `ImageStats.STANDARD` is a new name
for the set `NO_HASH` names, so `ImageStats.NO_HASH` now prints, and its `.name` reads, as `STANDARD`, and holds
`saturated_fraction` like the default. `NO_HASH` is deprecated and is removed in 2.0, with no runtime warning: name
`STANDARD`. `ImageStats.BASIC` is a new, smaller set that does not.

`VideoStats.ALL` now includes `BLUR_EDGE_WIDTH`, so it adds one column, a second `ExperimentalWarning` and a longer run.
So does a complement such as `~VideoStats.PERSISTENCE`, and a complement that left out every statistic that needs
OpenCV, such as `~(VideoStats.EGO | VideoStats.PERSISTENCE)`, now needs it. The default of {func}`.video_stats` returns
what it returned in v1.2. It is the new `VideoStats.BASIC`, so `VideoStats.NO_EGO`, the v1.2 name of the same set, now
prints, and its `.name` reads, as `BASIC`. `NO_EGO` is deprecated and is removed in 2.0, with no runtime warning: name
`BASIC`. The way to the v1.2 `ALL` is `VideoStats.ALL &
~VideoStats.BLUR`. The video statistic needs OpenCV, from the `dataeval[opencv]` extra, and measures frames at a short
side of 720 pixels at most. A blur request that measures videos at more than one short side raises one `UserWarning`.

The blur statistics are experimental ⚠️. The first image request and the first video request in a process each raise
{class}`~dataeval.exceptions.ExperimentalWarning`, and the column names and values may change in a later release, and
for videos so may the `blur_samples` keyword. An evaluator that requests them, such as `Outliers`, raises the warning
attributed to a line inside the library. Filter it by category when you want to silence it.

## The view operations declare the blur, spatial, saturation, context and noise statistics

The quality evaluators raise {class}`~dataeval.exceptions.StatsInvalidatedWarning` where a view operation's declaration
overlaps the statistics you asked for. A resize rescales a width in pixels, and a luminance mix changes which picture is
read, so v1.3 declares the blur statistics. An operation that clips a box, removes the boxes around it or changes their
classes changes the spatial statistics, one that moves the pixels around a box or removes its neighbors changes the
context statistics, and one that resizes or mixes channels moves the values that sat at a saturation endpoint and
changes the noise the noise statistics read, so v1.3 declares those too:

| Operation | v1.2 declared | v1.3 declares |
| --- | --- | --- |
| {class}`.Resize`, in every mode | the dimension statistics except the channel count, and `sharpness`, with more under `mode="pad"` | the same, and `ImageStats.BLUR`, `ImageStats.SPATIAL`, `ImageStats.PIXEL_SATURATED_FRACTION`, `ImageStats.CONTEXT` and `ImageStats.NOISE` |
| {class}`.SelectChannels` with `"gray"` | the channel count, `PIXEL` and `VISUAL` | the same, and `ImageStats.BLUR`, `ImageStats.PIXEL_SATURATED_FRACTION`, `ImageStats.CONTEXT` and `ImageStats.NOISE` |
| {class}`.Crop` | the dimension statistics except the channel count and the bit depth | the same, and `ImageStats.SPATIAL` and `ImageStats.CONTEXT` |
| {class}`.DetectionCrops` | the dimension statistics except the channel count | the same, and `ImageStats.PIXEL_SATURATED_FRACTION` and `ImageStats.NOISE` |
| {class}`.Filter` and {class}`.ClassFilter`, unless `drop="items"` | nothing | `ImageStats.SPATIAL` and `ImageStats.CONTEXT` |
| {class}`.Indices` with `exclude=True` and addresses of rows inside items | nothing | `ImageStats.SPATIAL` and `ImageStats.CONTEXT` |
| {class}`.Relabel` | nothing | `ImageStats.SPATIAL` and `ImageStats.CONTEXT` with the default `on_unmatched="drop"`, and the two class statistics with either value |
| {class}`.TorchvisionTransform` | `ImageStats.ALL` | `ImageStats.ALL`, which now holds every statistic v1.3 adds |

A request without a blur, spatial, saturation, context or noise flag gets the same warnings as before.
`ImageStats.PIXEL` holds saturation, so a request for it, and the default flags of {class}`.Outliers`, now warn for
`saturated_fraction` through a {class}`.Resize` or a {class}`.DetectionCrops`. An {class}`.Operation` of your own that
names a group narrower than `ALL`, such as `ImageStats.VISUAL`, covers none of them, so a request for `ImageStats.BLUR`,
`ImageStats.SPATIAL`, `ImageStats.PIXEL_SATURATED_FRACTION`, `ImageStats.CONTEXT` or `ImageStats.NOISE` raises no
warning for it.

## Spatial statistics

{class}`.ImageStats` has five new flags in the new group `ImageStats.SPATIAL`. Each compares a box with the other
boxes of its image or with the image's edges: how far its nearest neighbor is, how much of it lies inside the image, how
much the other boxes cover, and how much it overlaps a box of the same class and a box of another. They need boxes, so
they are NaN on an image's own row, and they report `spatial_status` and further facts about each row in the result's
`details`; the {class}`.ImageStats` docstring defines each. They are stable and raise no
{class}`~dataeval.exceptions.ExperimentalWarning`, though a request for `ImageStats.ALL` still raises it for blur.

`ImageStats.ALL` holds them, as it holds blur, and so does a complement such as `~ImageStats.HASH`. A request for
nothing but spatial or context statistics raises `ValueError` when the call has no boxes at all (no `boxes=` and none in
the dataset, or `per_target=False`), and warns once when boxes are given and the data holds none. A request that adds
other statistics returns NaN columns and warns once, unless it holds every statistic of `ImageStats.ALL` that needs no
box, less the color statistics where `color_rgb_channels` is not given: that request asks for everything, so the
statistics that cannot be measured read NaN without a warning, and a call with no boxes, or with `per_target=False`,
stays quiet under `ImageStats.ALL`. `ImageStats.ALL & ~ImageStats.SPATIAL` leaves them out. Where there are boxes, each
box is compared with every other box of its image, so the time grows with the square of the boxes in one image: time a
sample of your data before a long run. {class}`.Outliers` with `flags=ImageStats.ALL` judges the spatial columns on a
per-target call, and judges none on its default per-image path. Its default threshold can sit above the largest value a
column can take, and then it flags nothing: a column that runs only from 0 to 1 and is mostly 0, such as
`max_iou_other_class`, can get an upper bound above 1. Set a threshold for the column to flag its large values, such as
`outlier_threshold={"max_iou_other_class": ConstantThreshold(upper=0.5)}`.

The two class statistics, `SPATIAL_MAX_IOU_SAME_CLASS` and `SPATIAL_MAX_IOU_OTHER_CLASS`, read class labels. A dataset
supplies them, and explicit boxes take them through `labels=`. Any negative id is a missing label, which covers the
ignore id a dataset uses, so a negative id cannot be a class. Where a missing label could hide the true largest overlap
the value is NaN with the reason `missing_labels`, and where `labels` is absent every label is missing, so those columns
read NaN where a box overlaps another and 0.0 where none does. A dataset's floating-point labels are read as class ids:
a whole number is the id, NaN is missing, and a fractional value raises `ValueError`. The covered fraction takes memory
that grows with the square of the number of boxes that overlap one box, so a box that more than 1,000 others overlap
reads NaN with the reason `too_many_overlaps`. That limit is provisional.

## Context statistics

{class}`.ImageStats` has four new flags, `CONTEXT_SURROUND_INTENSITY_MEAN`, `CONTEXT_SURROUND_INTENSITY_STD`,
`CONTEXT_TARGET_SURROUND_CONTRAST` and `CONTEXT_SIGNAL_CLUTTER_RATIO`, in the new group `ImageStats.CONTEXT`. They add
the columns `surround_intensity_mean` and `surround_intensity_std`: the mean and the population standard deviation of
the intensity of the pixels around a box, and `target_surround_contrast` and `signal_clutter_ratio`: how far the box's
own mean intensity stands from that mean, relative to the surround's level and to its spread, with the sign kept. The
surround is a frame a quarter of the box's width and height wide, less the box and less every other valid box of the
image. Intensity is the value mapped to [0, 1] from the interval the image is measured against, as {func}`.image_stats`
resolves it for `value_range`, and averaged over the channels. They need boxes, so they are NaN on an image's own row,
and they report `context_status` and further facts about each row in the result's `details`; the {class}`.ImageStats`
docstring defines each. A box whose surround holds fewer than 32 measurable pixels reads NaN with the status
`insufficient_support`, which a small box does, and so does every box whose window other boxes cover, such as a box
inside an area marked as ignored. The two ratios are NaN there too, and also for a box with fewer than 90% of its pixels
valid, where `context_status` stays `ok` and `context_ratio_reason` reads `insufficient_target_support`. They are stable
and raise no
{class}`~dataeval.exceptions.ExperimentalWarning`.

{func}`.image_stats` has three new keywords, `surround_padding`, `surround_min_pixels` and `context_ratio_floor`,
which set the frame's width, the fewest measurable surround pixels and the least a ratio's denominator may be, 1/255 by
default, so that a dark or flat surround gives a bounded value. A floor of 0 raises. Their defaults, 0.25, 32 and
1/255, were chosen by no study, so they are provisional. The result records each with the statistics that read it in
`measurement_specs`, so {func}`.combine_stats_results` refuses results measured with different ones.

`ImageStats.ALL` holds them, and so does a complement such as `~ImageStats.HASH`, so {class}`.Outliers` with
`ImageStats.ALL` and `per_target=True` now also judges the two ratios. The rules for a request with no box rows are those
of the spatial statistics, and `ImageStats.ALL & ~ImageStats.CONTEXT` leaves them out. Each box reads its
whole window, so a per-target request for `ImageStats.ALL` now also reads pixels for every box, and the time grows with
the area of the boxes: time a sample of your data before a long run. On one machine, the 114,133 boxes of 2,846 frames
of up to 3840 x 2160 added about 17 seconds to the 51 that the same call took with a cheap box statistic. That
machine's timings differed by a fifth or more from run to run, and by more from one day to another. Without a
declared range, `uint8` data reads against (0, 255) and floating-point data within [0, 1] or [0, 255] against that
range, and any other data reads NaN with the status `unknown_range`, so declare the range of 16-bit data.

## Saturation statistic

{class}`.ImageStats` has a new flag, `PIXEL_SATURATED_FRACTION`, in `ImageStats.PIXEL`. It adds the column
`saturated_fraction`, the share of finite raw values at a clipping endpoint, and reports `saturated_status` and two more
values in the result's `details`; the {class}`.ImageStats` docstring says what each holds. {func}`.image_stats` has one
new keyword, `saturated_atol`. The endpoint is the upper bound of the interval the context and color statistics read:
the declared `value_range`, else 255 for `uint8` data, else 1 or 255 for float data within [0, 1] or [0, 255], and the
column is NaN with the status `unknown_range` where none applies.
[Saturation at a clipping endpoint](../concepts/ImageStatistics.md#saturation-at-a-clipping-endpoint) says what the
number can and cannot show. The statistic is stable.

`PIXEL` holds it, so `ImageStats.STANDARD`, `NO_HASH` and `ALL` do, and so do a complement such as `~ImageStats.HASH`,
the default of `image_stats` and the default flags of {class}`.Outliers`. Those requests gain a `saturated_fraction`
column and its details, and `Outliers` can judge it: an image with one clipped value among thousands can be flagged. The
column is NaN for data other than `uint8` and the two float conventions until a range is declared, so 12-bit data
stored in `uint16` reads NaN until its range is declared, as [Declared value ranges](#declared-value-ranges)
describes. `ImageStats.BASIC` does not hold it, and
`(ImageStats.STANDARD | ImageStats.HASH) & ~ImageStats.PIXEL_SATURATED_FRACTION` is the v1.2 set.

## Color statistics

{class}`.ImageStats` has five new flags in a new group, `ImageStats.COLOR`: `VISUAL_COLOR_LIGHTNESS_MEAN`,
`VISUAL_COLOR_CHROMA_MEAN`, `VISUAL_COLOR_ACHROMATIC_FRACTION`, `VISUAL_COLOR_HUE_COS_MEAN` and
`VISUAL_COLOR_HUE_SIN_MEAN`. They add the columns `color_lightness_mean`, `color_chroma_mean`,
`color_achromatic_fraction`, `color_hue_cos_mean` and `color_hue_sin_mean` for an image, each box and the background,
and, with the new keyword `per_surround=True`, `surround_color_*` columns for each box's surround, and report
`color_status` and four more values in the result's `details`. {func}`.image_stats` has three more new keywords:
`color_rgb_channels`, `color_min_pixels` and `color_chroma_threshold`. The statistics are experimental, and a call that
measures them raises an `ExperimentalWarning` the first time in a process. [Color
statistics](../concepts/ImageStatistics.md#color-statistics) says what the numbers can and cannot show.

Color is not readable from the pixels, so the statistics are measured only from channels you declare are sRGB red, green
and blue with `color_rgb_channels`, such as `(0, 1, 2)`. A request for them beside other statistics without it drops
them, with a warning once per process, a request for nothing else raises, and `ImageStats.ALL` holds them but drops
them, and logs it, so `ALL` returns the columns it returned before unless you give `color_rgb_channels`.
`ImageStats.BASIC`, `STANDARD`, `NO_HASH` and the default of `image_stats` do not hold them. {class}`.Outliers` and
{class}`.Duplicates` cannot take the keyword, so compute with `image_stats` and pass the result to `from_stats`, and
{class}`.QualityGate` does not accept the color statistics. The range follows the context statistics' rule: the declared
`value_range`, else (0, 255) for `uint8` and the two float conventions, and any other image reads NaN with the status
`unknown_range`.
`ImageStats.ALL & ~ImageStats.COLOR` leaves the group out of a request.

## Noise statistics

{class}`.ImageStats` has two new flags, `PIXEL_NOISE_STD` and `PIXEL_NOISE_VAR`, in the new group `ImageStats.NOISE`.
They add the columns `noise_std` and `noise_var`, an estimate of the standard deviation and the variance of additive
white Gaussian noise from the pixels alone, for an image, each box, the background, each channel group and, with
`per_surround=True`, each box's surround, and report `noise_status` and `noise_neighborhoods` in the result's
`details`; the {class}`.ImageStats` docstring says what each holds. A new core function, {func}`.noise_immerkaer`,
computes the estimate for one array. {func}`.image_stats` has no new keyword for them. The statistics are stable and
raise no {class}`~dataeval.exceptions.ExperimentalWarning`, but the surround view is experimental, and the first call
in a process that measures any statistic over it raises the warning for the view. [Noise
statistics](../concepts/ImageStatistics.md#noise-statistics) says what the numbers can and cannot show.

`ImageStats.ALL` holds them, and so does a complement such as `~ImageStats.HASH`, so those requests gain two columns
and two details, and {class}`.Outliers` with `flags=ImageStats.ALL` now judges `noise_std` and `noise_var`. Texture
reads as noise, so an image of a busy scene can be flagged as well as a noisy one. `ImageStats.PIXEL`, `STANDARD`,
`BASIC`, `NO_HASH` and the default of `image_stats` do not hold them, and `ImageStats.ALL & ~ImageStats.NOISE` leaves
them out. The values are in the data's own units. Under `normalize_pixel_values=True` the range follows the context
statistics' rule, and any other image reads NaN with the status `unknown_range`. Measured on the built code, on one
machine, `ImageStats.NOISE` took about 0.02 seconds on one 756 x 1344 RGB `uint8` frame and about half a second on a
4000 x 6000 one, under a quarter of the time the default request took on the same frames, and its allocations peaked
near 1 GB on the larger frame.

## Declared value ranges

A dataset can declare the interval an image's values occupy, as a `(low, high)` pair under `value_range` in that datum's
metadata. {func}`.image_stats` reads it for each image, for every statistic that reads an interval (the histogram and
entropy, the visual statistics, blur, `DIMENSION_DEPTH`, saturation, the context and color statistics, and the noise
statistics under `normalize_pixel_values`), so one collection can hold sensors of different depths, and
{class}`.Outliers` and {class}`.Duplicates` read it through {func}`.image_stats`. The `value_range=` argument beats it,
and a channel group's own range beats both. An iterable of arrays has no metadata.

The metadata key is experimental ⚠️. The first declaration read in a process raises
{class}`~dataeval.exceptions.ExperimentalWarning`, and the key and the shape of its value may change in a later release.
It is a claim about the pixels, so a {class}`.TorchvisionTransform` that rescales an image drops it from that datum, and
{class}`.Metadata` does not read it as a factor. A dataset that already holds a `value_range` key with another meaning
now has it read, and a pair that is not finite and ordered raises when a statistic that reads an interval is requested.

A declared range that the values leave is now logged for every statistic that reads it, naming the images, where only
the histogram said so. The `value_range=` argument of {func}`.image_stats` is stable.

`DIMENSION_DEPTH` now reads a depth from a declared range of `(0, 2**n - 1)` on integer data, where it reported NaN for
any declaration, so a call with `value_range=(0, 4095)` on `uint16` data reports 12.

---

## Near-duplicate video segments

{func}`.hash_neighbors` has two new arguments, `partition` and `k`, and {class}`.Duplicates` has a new option,
`segment_neighbors`. All three are experimental ⚠️ and raise {class}`~dataeval.exceptions.ExperimentalWarning` once per
process. `Duplicates` raises it where `segment_neighbors` is set, and not for the `partition` and `k` it passes itself.

The segment search for video now passes `partition`, which reports only the pairs whose two labels differ, so it no
longer enumerates a pair inside one sequence. A video with a long static stretch holds quadratically many identical
frames, and two such videos used to exceed the pair budget, `max_pairs`, so the pair lost its segments, including a
stretch the two videos truly share. Those pairs are now searched and can yield segments. A pair of videos that fit the
budget before returns the same pairs and distances. When the pairs crossing between two videos still exceed the budget,
the pair still loses its segments, and the log line for that moves from INFO to WARNING and names `segment_neighbors`.

`k` and `segment_neighbors` keep only each frame's `k` nearest matches, so that videos whose crossing pairs are still
quadratic can be searched. `None`, the default, leaves every result as before. A frame with a match still has one, but
a segment's extent and boundaries can shrink or move. 10 is a provisional starting point, chosen on simulated static
runs. The repr and the config of a `Duplicates` gain a `segment_neighbors` entry, `None` unless set.

---

## `image_stats` refuses boxes that are not four numbers and takes labels

An entry of `boxes=` that was a row of the wrong length was logged and measured as the box `(0, 0, 0, 0)`, which counts
as an invalid box. An entry that was a single number, such as one flat box `(x0, y0, x1, y1)` passed where a list of
boxes belongs, was measured as the full-image box without a message. A dataset target whose `boxes` had more than four
columns kept the first four and dropped the rest. {func}`.image_stats`, the deprecated `compute_stats` alias and
{func}`.unzip_dataset` now raise `ValueError` for all three, naming the image and the box:

```python
image_stats(images, boxes=[[(0, 0, 10)]])
# v1.2: logged, and measured as the box (0, 0, 0, 0)
# v1.3: ValueError: image 0, box 0: expected 4 values (x0, y0, x1, y1), got 3 values; ...
```

Give every box four numbers, and pass class ids through `labels=` instead of a fifth column. A box that still held NaN or
an infinity after conversion, such as `(nan, 0, 10, 10)` or `(0, 0, inf, 10)`, raised `ValueError` or `OverflowError`
from inside the library. It is now measured as the box `(0, 0, 0, 0)`, so `invalid_box` is True for it and
`invalid_box_count` counts it. A NaN in the second corner, such as `(0, 0, 10, nan)`, never raised and is unchanged: it
is measured as a box of zero height.

{func}`.image_stats` has a new keyword, `labels=`: one sequence of integer class ids per image, one id per box in that
image's `boxes` entry. It requires `boxes=` and raises where the lengths differ. The two class statistics of
`ImageStats.SPATIAL` read it and no other statistic does, so it changes no other result. It is experimental ⚠️: the
keyword may change, and it raises no warning.

---

## Items that hold several images

An item of more than three dimensions, such as a batch of shape `(B, C, H, W)` from a data loader, was measured as its
first image. {func}`.image_stats`, {class}`.Outliers` and {class}`.Duplicates` saw only image 0, so the rest of the batch
was never measured, and two batches that began with the same image were reported as exact duplicates.
{func}`~dataeval.utils.preprocessing.normalize_image_shape`, which the image statistics, the hashes and the view
operations read images through, now raises {class}`~dataeval.exceptions.ShapeMismatchError` for such an item. Leading
axes of size 1, as in `(1, C, H, W)`, are still dropped, so a single image with a batch axis is measured as before.

---

## Box coordinates in Metadata

The `box` column of {attr}`.Metadata.dataframe` and {meth}`.Metadata.rows_at` is `Array(Float64, 4)`, the coordinates
as the dataset's targets give them. v1.2 stored them as `Float32`, so a coordinate such as `473.07` read back as
`473.070007`, which moves the overlap of two small boxes in a large image by up to about 5e-5. A box takes 16 more bytes.
Cast the column with `pl.col("box").cast(pl.Array(pl.Float32, 4))` where your code needs the v1.2 dtype.

---

## Embeddings files

When the rows of an {class}`.Embeddings` with a `path` are estimated to take more than `memory_threshold` of the
available memory, it keeps them in a memory-mapped file. That file is now a `.npy` file with a NumPy header, so
`np.load(path, mmap_mode="r")` reads it. v1.2 wrote the raw values with no header, so `np.load` refused the file as
pickled data, and code that read it with `np.memmap(path, dtype=..., shape=...)` now reads the header as values. A file
written by v1.2 still has no header.

{meth}`.Embeddings.save` with another path now copies those rows there, and setting `path` copies them and moves the
store onto the copy. v1.2 flushed the instance's own file and wrote nothing at the new path. Either raises `ValueError`
for the file of another {class}`.Embeddings` in the process, which it would have overwritten. A file name given to
`save` is kept as given: v1.2 added `.npy` to a name such as `rows.bin` when the rows were in memory.

---

## Two columns of one name

{func}`.image_stats` raises `ValueError` when two of its views or channel groups would give two columns, or two
details, one name, and names the column. Before, the second one kept its value and the first was lost without a word.
Rename a channel group so that every column name differs.

---

## Frame statistics

{func}`.frame_stats` measures, for each frame of a video, the seconds since the previous frame (`elapsed_time_s`) and
whether the frame is identical to it (`repeat_frame`). `FrameStats.TIMING` reads timestamps only. The result attaches to
a tracking dataset with {meth}`.Metadata.add_factors`, which also adds the sequence roll-ups `elapsed_time_s_median`,
`elapsed_time_s_std` and `repeat_frame_fraction`. It is experimental and raises
{class}`~dataeval.exceptions.ExperimentalWarning` on the first call in a process. No existing call changes.

---

## Track gap and heading

{func}`.track_stats` adds two columns to every result: `max_gap_length`, the longest run of frames in which a track is
absent between two of its observations, and `net_heading_rad`, the direction in radians from a track's first to its last
box center. A heading of 0 points right, and a positive angle turns clockwise on the image. Read a heading only where
`net_displacement` is large, since where a track barely moved the heading is set by box jitter.

```python
result = track_stats(dataset)
metadata.add_factors(result, level="track", key="track_id")
```

No existing column changes. Attaching the result now brings two more track factors, and code that lists a result's
columns sees two more.

---

## A track id given to two detections in one frame

A tracker gives each id to one object per frame. A target that gave one id to two detections of a frame was accepted:
{class}`.Metadata` and {func}`.build_tracks` made a track with two boxes in one frame, and {func}`.track_stats` returned
an infinite `mean_speed` for it, from a step of zero frames. They now raise `ValueError`, naming the id and the frame,
as does `track_stats` for a hand-built `Track` whose `frame_indices` do not strictly increase. An id of `-1` marks a
detection no tracker linked and may repeat. The VisDrone2019-MOT validation split, 118,127 detections in 2,846 frames,
holds no frame with a repeated id.

A track id or a label that is not a whole number a signed 64-bit integer holds, such as `1.5`, NaN or a `uint64` above
`2**63 - 1`, also raises `ValueError` now. Before, it was wrapped or truncated without a word: the largest `uint64` read
as `-1`, which left the detection untracked, and `1.5` joined track 1. A whole number held as a float, such as `3.0`, is
still read as `3`.

---

## Track ids of crops

{class}`.DetectionCrops` gains `track_ids`, one track id per crop in crop order. `-1` marks a detection no tracker linked,
and every crop of a dataset that carries no track ids. A track id is unique only within a video, so name a crop's track
together with its video and frame, which `frames.frame_map[crops.item_indices]` gives for crops over a
{class}`.SequenceFrames` view. No existing property changes.

`SequenceFrames.track_map` now reads track ids the way {class}`.Metadata` does. A frame whose `track_ids` are shorter
than its boxes gets one row per detection, padded with `-1`. Before, it got one row per id, so its rows did not line up
with the per-detection statistics of the same frame.

---

## Track steps

{func}`.track_steps` measures, for each detection of a tracking dataset, the step from the previous observation of its
track: the distance moved in diagonals of the previous box, that distance per frame and per second, how much the two
boxes overlap, and how much the box scaled. A row that cannot be measured is NaN, and `details["step_status"]` says why:
`untracked`, `first_observation`, `gap_exceeds_limit`, `invalid_box`, `reversed_box`, `geometry_change` or `ok`.
`max_frame_delta` bounds the frames a step may span and defaults to 1. A step is not conditioned on shot boundaries or
on camera motion. The result attaches to the instance rows with {meth}`.Metadata.add_factors`. It is experimental and
raises {class}`~dataeval.exceptions.ExperimentalWarning` on the first call in a process. No existing call changes.

---

## Track paths in embedding space

{func}`.track_path_stats` treats each track as a path through embedding space, such as the embeddings of its crops, and
measures three things for it: `path_displacement`, the distance between the mean of the first third of the track's rows
and the mean of the last third, `path_displacement_null`, the value that distance would have on average if the order of
the rows carried nothing, and `path_direction`, the unit vector from the first mean to the last. A track with fewer than
`min_points` rows, 60 by default, is NaN, and the call warns with the count. The result attaches to the track rows with
{meth}`.Metadata.add_factors` and `level="track", key="track_id"`. It is experimental and raises
{class}`~dataeval.exceptions.ExperimentalWarning` on the first call in a process. No existing call changes.

---

## Read record on View

`View(dataset, record_reads=True)` keeps each datum's target and metadata, without its pixels, the first time the view
reads it. {class}`.Metadata` built from the view afterward reads only the items the pass did not. Run the pass that reads
the pixels first, such as {class}`.Embeddings` or {class}`.Outliers`: building the metadata first gains nothing, because
the pass that follows needs the pixels. The record is held for the life of the view, so it costs memory in proportion to
the targets and metadata. It has no effect on a tracking dataset, on an item that is not an `(item, target, metadata)`
tuple, or on a pickled copy. It is experimental and raises {class}`~dataeval.exceptions.ExperimentalWarning` when the
first view that sets it is constructed in a process. No existing call changes.

---

## Load threads

{func}`.set_load_threads`, and the {func}`.use_load_threads` context manager, load several dataset items at once
wherever DataEval reads a whole dataset item by item: {class}`.Embeddings`, {class}`.Metadata`, {func}`.image_stats` and
so {class}`.Outliers` and {class}`.Duplicates`, the extractors called on a dataset and so the drift and OOD detectors
given one, {class}`.Feasibility` given a model, {func}`.unzip_dataset`, and {class}`.Filter`, {class}`.Relabel`,
{class}`.ClassBalance` and {class}`.DetectionCrops` as a view is built. It is off by default, and results and their
order do not change. With it on, `dataset[i]` is called from several threads at once, so the dataset must be safe for
that: one that holds an open file handle can return wrong data, or raise. It helps when each read takes more than a few
milliseconds, such as decoding a large image, and it can be slower than the serial loop when reads are short. It is
separate from {func}`.set_max_processes`, the worker processes {func}`.image_stats` computes in while it reads in these
threads. A dataset already in memory, a multi-object tracking dataset and a {class}`.SequenceFrames`, with any view
built on it, are read serially; {func}`.video_stats`, {func}`.frame_stats` and {func}`.ego_stats` measure several videos
at once under {func}`.set_max_processes` instead. It is experimental and raises
{class}`~dataeval.exceptions.ExperimentalWarning` the first time more than one thread is asked for in a process. No
existing call changes.

---

## Several extractors in one pass

{meth}`.Embeddings.compute_multi` takes a dataset and a mapping of extractors and returns one computed
{class}`.Embeddings` for each, from one read of the dataset: each batch is read once and given to every extractor in
turn. Each result is an ordinary {class}`.Embeddings`, equal to what its extractor gives on its own with the same batch
size, unless the extractor draws random numbers, and it goes wherever one is accepted. Each extractor reads its own copy
of every NumPy image and tensor, so one that changes its input in place does not change what the next reads. With
`path`, each extractor gets a directory of its own under it, which holds its memory-mapped file when all the embeddings
together are too large for memory, and the file its `save()` writes. Each {class}`.TorchExtractor` runs its own forward
pass, and a {class}`.TorchLayers` reads several layers of one model in one forward pass per batch, each stored under
`<key>/<layer>` as its own {class}`.Embeddings`, equal to that layer's own {class}`.TorchExtractor`. A
{class}`.TorchLayers` cannot be called, so it goes only to {meth}`.Embeddings.compute_multi`. Two or more
{class}`.VideoTorchExtractor` share one walk of each video, holding no more than one clip of it for each, or copying a
video held in memory as a tensor for each, and any other extractor walks the video again. It is experimental and raises
{class}`~dataeval.exceptions.ExperimentalWarning` on the first call in a process. No existing call changes.

---

## PCA noise estimate

{func}`.noise_pca` estimates the standard deviation of white Gaussian noise in each channel of one image from the
smallest eigenvalue of the covariance of its 7x7 patches, and returns the same `NoiseResult` as
{func}`.noise_immerkaer`. A channel needs 784 patches with no masked pixel, about a 34x34 region, and reads NaN with
fewer. Nothing in DataEval calls it. It is experimental and raises {class}`~dataeval.exceptions.ExperimentalWarning` on
the first call in a process. No existing call changes.

---

## `ego_stats` refuses a pair with a slow mover or two flow groups

{func}`.ego_stats` now refuses a pair that a camera and one mover explain much better than one smooth camera motion
does, such as a slow mover over a still camera. A pair whose flow falls in two groups, such as a camera moving past a
near cliff and a distant sea, can be refused too. A pair that was trusted can therefore be refused, with `ego_trusted`
False and its kinematics NaN. The roll-ups of {func}`.video_stats` with `VideoStats.EGO` see that, and
{class}`.CameraTravel` keeps more frames, marked unmeasured. In
[a check on 19 drone clips](../concepts/ValidationAndTrust.md#studies-on-real-footage), at a gap of one frame, 0.3% of
the pairs that had been trusted were refused, 1.4% to 3.2% in three of the clips and 0.02% in the other sixteen, and
none was newly trusted. A refused pair means the camera could not be told apart from a mover, or the flow fell into two
groups; for a slow mover over a still camera, `mover_frac` stays near 0.

---

## Object detection in Feasibility

{class}`.Feasibility` judges AP on one class of an object detection dataset. A requirement whose `max_detections` K is
below `Feasibility(max_objects=...)` gets a capacity envelope, an upper bound on the AP that any detector with at most K
detections per image can reach, read from the targets alone. A detector's detections passed as `predictions=` add a
witness, and `predictions=` is optional when every requirement's K is below `max_objects`. In v1.2 an object detection
call raised `NotImplementedError`. It now runs, or raises `ValueError` when `Feasibility(max_objects=...)` is missing,
or when `predictions=` is missing and a requirement's K is at or above `max_objects`. An object detection
{class}`.TargetSpec` needs `max_detections` and no longer needs `ap_functional`, which defaults to
`"population_ap_integral"` for every AP target. No such target could be evaluated in v1.2. The `determinations` table
gains the columns `iou` and `max_detections`, null for classification; the `assumptions` of the `bounds` table gain the
member `max_objects_holds`; and `meta().state` records `max_objects`. The Enum of the `source` column of `bounds`, and
of the `minimum_source` and `witness_source` columns of `determinations`, gains the member `capacity`. The `sample`
Enum of `bounds` gains `all_items`. Both change the dtypes for every call, classification included.

## What to do

1. Name `ImageStats.BASIC`, `ImageStats.STANDARD` or `VideoStats.BASIC`, or single statistics, where your code needs
   columns that do not change between releases. Where you pass `ImageStats.ALL` and want the v1.2 columns, pass
   `(ImageStats.STANDARD | ImageStats.HASH) & ~ImageStats.PIXEL_SATURATED_FRACTION`, and intersect a complement `~X`
   with the same set. For videos, pass `VideoStats.ALL & ~VideoStats.BLUR`, and add `& ~VideoStats.BLUR` to a
   complement.
2. To measure blur, request `ImageStats.BLUR`, expect the `ExperimentalWarning`, and compare values only between images
   of one resolution.
3. To measure the blur of a video, request `VideoStats.BLUR`, expect the `ExperimentalWarning`, and compare values only
   between videos of one frame size.
4. Add `| ImageStats.BLUR` to the `invalidates` of your own `Operation` if it changes the picture and does not declare
   `ImageStats.ALL`, `| ImageStats.SPATIAL` if it clips, moves, removes or relabels boxes, `| ImageStats.CONTEXT` if it
   moves or removes boxes or changes the pixels around them, and `| ImageStats.PIXEL_SATURATED_FRACTION` and
   `| ImageStats.NOISE` if it resizes or mixes channels.
5. If the log says a pair of videos lost its segments to the pair budget, set `Duplicates(segment_neighbors=10)`, expect
   the `ExperimentalWarning`, and check the segments it then reports, since a cap can move their boundaries.
6. Give every box in `boxes=`, and in a dataset's targets, four numbers, and pass class ids through `labels=`.
7. To find isolated, overlapped or frame-truncated targets, request `ImageStats.SPATIAL` with boxes, `labels=` and
   `per_image=False`.
8. To measure how much of an image sits at a clipping endpoint, request `ImageStats.PIXEL_SATURATED_FRACTION`, and declare
   `value_range` as `(0, 4095)` in the datum metadata for 12-bit data stored in `uint16`.
9. Where a tracking dataset raises for a repeated track id, give the extra detections ids of their own, or `-1` to leave
   them untracked.
10. To measure the step each detection takes, call `track_steps(dataset)`, expect the `ExperimentalWarning`, and read
    `details["step_status"]` where a measurement is NaN.
11. To measure the intensity around a box, and how far the box stands from it, request `ImageStats.CONTEXT` with boxes
    and `per_image=False`, declare `value_range` where you compare images, read `context_status` and `context_ratio_reason`
    before you treat a NaN as missing data, and read the `*_floored` details before you rank boxes by a ratio.
12. To measure color, request `ImageStats.COLOR` with `color_rgb_channels` naming the channels that are sRGB red, green
    and blue, expect the `ExperimentalWarning`, declare `value_range` for 16-bit images, and read
    `color_status` before you treat a NaN as missing data. Add `per_surround=True` to compare each box's color with the
    color around it.
13. To estimate the noise in images, request `ImageStats.NOISE`, read `noise_status` before you treat a NaN as missing
    data, compare readings only between images of similar content, and compare their distributions rather than single
    readings.
14. To stop reading a dataset a second time for its metadata, build the {class}`.View` with `record_reads=True`, run
    {class}`.Embeddings` or {class}`.Outliers` on it first, build {class}`.Metadata` from the same view, and expect the
    `ExperimentalWarning`.
15. To load a dataset with slow reads faster, call `set_load_threads(4)`, expect the `ExperimentalWarning`, check on your
    data that it is faster, since it can be slower when each read is short, and check that your dataset is safe to read
    from several threads.
16. To embed one dataset with several extractors and read it once, call
    `Embeddings.compute_multi(dataset, {"a": extractor_a, "b": extractor_b}, batch_size=32)`, expect the
    `ExperimentalWarning`, and use each returned `Embeddings` as before.
17. To read several layers of one torch model in one forward pass, pass `TorchLayers(model, ["layer3", "layer4"])` as
    one of the extractors of `Embeddings.compute_multi`, expect the `ExperimentalWarning`, and read each layer's
    `Embeddings` under `"<key>/layer3"` and `"<key>/layer4"`.
18. If your dataset's items are batches of images, give it one image per item: split each batch into its images, or pass
    the dataset the data loader reads rather than the loader.
19. To name the video, frame and track of each crop of a tracking dataset, build {class}`.DetectionCrops` over
    {class}`.SequenceFrames` and read `crops.track_ids` and `frames.frame_map[crops.item_indices]`.
20. If your code needs the `box` column of {class}`.Metadata` as `Float32`, cast it.
21. To measure how far, and in which direction, the embeddings of each track travel, call
    `track_path_stats(embeddings, track_ids, frame_indices, sequence_indices)`, expect the `ExperimentalWarning`, and
    compare `path_displacement` across tracks. Do not rank tracks by its ratio to `path_displacement_null`, which rises
    with the length of a track.
22. If your code reads the memory-mapped file of an {class}`.Embeddings`, load it with `np.load(path, mmap_mode="r")`,
    and compute the embeddings again for a file v1.2 wrote.
23. To judge a detector's AP on one class, give each {class}`.TargetSpec` `task="OD"`, `class_name`, `iou` and
    `max_detections`, pass the detections as `predictions=`, and set `Feasibility(max_objects=...)`. Leave out
    `predictions=`, with each requirement's `max_detections` K below `max_objects`, to ask whether any detector with that
    cap could reach the required AP.
