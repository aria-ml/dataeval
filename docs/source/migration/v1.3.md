# Migrating from v1.2 to v1.3

v1.3 adds experimental blur statistics to {func}`.image_stats` and {func}`.video_stats`. This page lists what that
means for existing code.

## At a glance

| Area | You are affected if you | Status |
| --- | --- | --- |
| [ALL and complements](#blur-statistics) | pass `stats=ImageStats.ALL` or `stats=VideoStats.ALL`, run `Outliers(flags=ImageStats.ALL)`, build a request with `~`, or read the `.name` of `ImageStats.NO_HASH` or `VideoStats.NO_EGO` | changed |
| [Blur statistics](#blur-statistics) | want the width of the edges in an image, or one edge width for each video, as a measure of how soft it is | additive (experimental) |
| [Invalidation declarations](#the-view-operations-declare-the-blur-statistics) | read `Resize(...).invalidates` or `SelectChannels("gray").invalidates`, or name `invalidates` group by group in your own `Operation` | changed |

If none applies, your code needs no change.

---

## Blur statistics

{class}`.ImageStats` has two new flags, `VISUAL_BLUR` and `VISUAL_BLUR_DIRECTIONALITY`, in the new group
`ImageStats.BLUR`. They add the columns `blur` and `blur_directionality`. {class}`.VideoStats` has one new flag,
`BLUR_LEVEL`, in the new group `VideoStats.BLUR`. It adds the column `blur_level`, and {func}`.video_stats` has a new
keyword, `blur_samples`. See [Blur statistics](../concepts/BlurStatistics.md) for what the values mean and what they
cannot tell you.

```python
from dataeval.core import image_stats
from dataeval.flags import ImageStats

stats = image_stats(images, stats=ImageStats.BLUR)
```

`ImageStats.ALL` now includes the blur flags, and `VISUAL`, `VISUAL_BASIC` and `NO_HASH` do not. The default of
{func}`.image_stats` is what `ALL` was in v1.2, so a call that passes no `stats` returns what it returned in v1.2. A
request for `ALL`, or for a complement such as `~ImageStats.HASH`, now measures blur. It costs much more than
`sharpness`: on one machine a 3840x2160 frame took over a second, and nothing caps the size of an image. `ALL` holds
every statistic of a release, so a later release can add to it again. {class}`.Outliers` with `flags=ImageStats.ALL` now
judges the blur statistics too. `ImageStats.STANDARD` is a new name for the set `NO_HASH` names, and `NO_HASH` stays, so
`ImageStats.NO_HASH` now prints, and its `.name` reads, as `STANDARD`. `ImageStats.BASIC` is a new, smaller set.

`VideoStats.ALL` now includes `BLUR_LEVEL`, so it adds one column, a second `ExperimentalWarning` and a longer run. So
does a complement such as `~VideoStats.PERSISTENCE`, and a complement that left out every statistic that needs OpenCV,
such as `~(VideoStats.EGO | VideoStats.PERSISTENCE)`, now needs it. The default of {func}`.video_stats` returns what it
returned in v1.2. It is the new `VideoStats.BASIC`, and `NO_EGO` stays as another name for the same set, so
`VideoStats.NO_EGO` now prints, and its `.name` reads, as `BASIC`. The way to the v1.2 `ALL` is
`VideoStats.ALL & ~VideoStats.BLUR`. The video statistic needs OpenCV, from the `dataeval[opencv]` extra, and measures
frames at a short side of 720 pixels at most. A blur request that measures videos at more than one short side raises
one `UserWarning`.

The blur statistics are experimental ⚠️. The first image request and the first video request in a process each raise
{class}`~dataeval.exceptions.ExperimentalWarning`, and the column names and values may change in a later release, and
for videos so may the `blur_samples` keyword. An evaluator that requests them, such as `Outliers`, raises the warning
attributed to a line inside the library. Filter it by category when you want to silence it.

## The view operations declare the blur statistics

The quality evaluators raise {class}`~dataeval.exceptions.StatsInvalidatedWarning` where a view operation's
declaration overlaps the statistics you asked for. A resize rescales a width in pixels, and a luminance mix changes
which picture is read, so v1.3 declares the blur statistics:

| Operation | v1.2 declared | v1.3 declares |
| --- | --- | --- |
| {class}`.Resize`, in every mode | the dimension statistics except the channel count, and `sharpness`, with more under `mode="pad"` | the same, and `ImageStats.BLUR` |
| {class}`.SelectChannels` with `"gray"` | the channel count, `PIXEL` and `VISUAL` | the same, and `ImageStats.BLUR` |

A request without a blur flag gets the same warnings as before. An {class}`.Operation` of your own that names a group
narrower than `ALL`, such as `ImageStats.VISUAL`, does not cover blur, so a request for `ImageStats.BLUR` raises no
warning for it.

## What to do

1. Name `ImageStats.BASIC`, `ImageStats.STANDARD` or `VideoStats.BASIC`, or single statistics, where your code needs
   columns that do not change between releases. Where you pass `ImageStats.ALL` and want the v1.2 columns, pass
   `ImageStats.ALL & ~ImageStats.BLUR`, and intersect a complement `~X` with the same set. For videos, pass
   `VideoStats.ALL & ~VideoStats.BLUR`, and add `& ~VideoStats.BLUR` to a complement.
2. To measure blur, request `ImageStats.BLUR`, expect the `ExperimentalWarning`, and compare values only between images
   of one resolution.
3. To measure the blur of a video, request `VideoStats.BLUR`, expect the `ExperimentalWarning`, and compare values only
   between videos of one frame size.
4. Add `| ImageStats.BLUR` to the `invalidates` of your own `Operation` if it changes the picture and does not declare
   `ImageStats.ALL`.
