# Migrating from v1.2 to v1.3

v1.3 adds experimental blur statistics to {func}`.image_stats`. This page lists what that means for existing code.

## At a glance

| Area | You are affected if you | Status |
| --- | --- | --- |
| [ALL and complements](#blur-statistics-for-images) | pass `stats=ImageStats.ALL`, run `Outliers(flags=ImageStats.ALL)`, or build a request with `~` | changed |
| [Blur statistics](#blur-statistics-for-images) | want the width of the edges in an image, as a measure of how soft it is | additive (experimental) |
| [Invalidation declarations](#the-view-operations-declare-the-blur-statistics) | read `Resize(...).invalidates` or `SelectChannels("gray").invalidates`, or name `invalidates` group by group in your own `Operation` | changed |

If none applies, your code needs no change.

---

## Blur statistics for images

{class}`.ImageStats` has two new flags, `VISUAL_BLUR` and `VISUAL_BLUR_DIRECTIONALITY`, in the new group
`ImageStats.BLUR`. They add the columns `blur` and `blur_directionality`. See
[Blur statistics](../concepts/BlurStatistics.md) for what the values mean and what they cannot tell you.

```python
from dataeval.core import image_stats
from dataeval.flags import ImageStats

stats = image_stats(images, stats=ImageStats.BLUR)
```

`ImageStats.ALL` now includes the blur flags, and `VISUAL`, `VISUAL_BASIC` and `NO_HASH` do not. The default of
{func}`.image_stats` is unchanged: `ImageStats.NO_HASH | ImageStats.HASH`, what `ALL` was in v1.2, so a call that passes
no `stats` returns what it returned in v1.2. A request for `ALL`, or for a complement such as `~ImageStats.HASH`, now
measures blur. It costs much more than `sharpness`: on one machine a 3840x2160 frame took over a second, and nothing
caps the size of an image. `ALL` holds every statistic of a release, so a later release can add to it again.
{class}`.Outliers` with `flags=ImageStats.ALL` now judges the blur statistics too. For columns that do not change, name
the new `ImageStats.BASIC` or single statistics.

The blur statistics are experimental ⚠️. The first request in a process raises
{class}`~dataeval.exceptions.ExperimentalWarning`, and the column names and values may change in a later release. An
evaluator that requests them, such as `Outliers`, raises the warning attributed to a line inside the library. Filter it
by category when you want to silence it.

---

## The view operations declare the blur statistics

The quality evaluators raise {class}`~dataeval.exceptions.StatsInvalidatedWarning` where a view operation's
declaration overlaps the statistics you asked for. A resize rescales a width in pixels, and a luminance mix changes
which picture is read, so v1.3 declares the blur statistics:

| Operation | v1.2 declared | v1.3 declares |
| --- | --- | --- |
| {class}`.Resize`, in every mode | the dimension statistics except the channel count, and `sharpness`, with more under `mode="pad"` | the same, and `ImageStats.BLUR` |
| {class}`.SelectChannels` with `"gray"` | the channel count, `PIXEL` and `VISUAL` | the same, and `ImageStats.BLUR` |

A request without a blur flag gets the same warnings as before. An {class}`.Operation` of your own that names a group
narrower than `ALL`, such as `ImageStats.VISUAL`, does not cover blur, so a request for `ImageStats.BLUR` raises no
warning for it.

---

## What to do

1. Name `ImageStats.BASIC` or single statistics where your code needs columns that do not change between releases.
   Where you pass `ImageStats.ALL` and want the v1.2 columns, pass `ImageStats.ALL & ~ImageStats.BLUR`, and intersect
   a complement `~X` with the same set.
2. To measure blur, request `ImageStats.BLUR`, expect the `ExperimentalWarning`, and compare values only between images
   of one resolution.
3. Add `| ImageStats.BLUR` to the `invalidates` of your own `Operation` if it changes the picture and does not declare
   `ImageStats.ALL`.
