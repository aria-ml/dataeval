# Migrating from v1.2 to v1.3

v1.3 adds experimental blur statistics to {func}`.image_stats` and {func}`.video_stats`, spatial statistics that compare
a box with its neighbors, a saturation statistic that counts the values at a clipping endpoint, experimental arguments
that let {class}`.Duplicates` search videos with long static stretches for shared segments, an experimental
{func}`.frame_stats` that measures the time between frames and exact repeats, and two new columns of
{func}`.track_stats`, the longest gap and the net heading of a track. It also makes {func}`.image_stats` refuse boxes
that are not four numbers, and {class}`.Metadata`, {func}`.build_tracks` and {func}`.track_stats` refuse a track that
cannot be stepped through. This page lists what that means for existing code.

## At a glance

| Area | You are affected if you | Status |
| --- | --- | --- |
| [ALL and complements](#blur-statistics) | pass `stats=ImageStats.ALL` or `stats=VideoStats.ALL`, run `Outliers(flags=ImageStats.ALL)`, build a request with `~`, or read the `.name` of `ImageStats.NO_HASH` or `VideoStats.NO_EGO` | changed |
| [Default image statistics](#saturation-statistic) | call `image_stats` with no `stats`, request `ImageStats.PIXEL`, `NO_HASH` or the `pixel` family of dataeval-flow, or run `Outliers` with its default flags, and read the columns | additive |
| [Blur statistics](#blur-statistics) | want the width of the edges in an image, or one edge width for each video, as a measure of how soft it is | additive (experimental) |
| [Invalidation declarations](#the-view-operations-declare-the-blur-spatial-and-saturation-statistics) | read `Resize(...).invalidates`, `SelectChannels("gray").invalidates` or `DetectionCrops.invalidates`, or name `invalidates` group by group in your own `Operation` | changed |
| [Video segment search](#near-duplicate-video-segments) | run `Duplicates` on videos that hold long static stretches, or read its log for a pair that lost its segments | changed |
| [Neighbor arguments](#near-duplicate-video-segments) | want `hash_neighbors(partition=..., k=...)`, or `Duplicates(segment_neighbors=...)` to keep only each frame's nearest matches | additive (experimental) |
| [Boxes that are not four numbers](#image_stats-refuses-boxes-that-are-not-four-numbers-and-takes-labels) | pass `boxes=` rows that do not hold four numbers to `image_stats` or `compute_stats`, give a dataset's targets boxes with more than four columns, or call {func}`.unzip_dataset` on such a dataset | **now raises** |
| [`labels=`](#image_stats-refuses-boxes-that-are-not-four-numbers-and-takes-labels) | want class labels carried alongside explicit boxes | additive (experimental) |
| [Spatial statistics](#spatial-statistics) | want to find isolated, overlapped or frame-truncated targets, or boxes that overlap a box of another class, or build a request with `~` | additive |
| [Saturation statistic](#saturation-statistic) | want the share of values at a clipping endpoint, or run any request above on 12-bit data stored in `uint16` | additive |
| [Declared value ranges](#declared-value-ranges) | give `value_range=` to `image_stats` and read `DIMENSION_DEPTH` or the logs, or keep a `value_range` key in your datum metadata | changed |
| [`value_range` in datum metadata](#declared-value-ranges) | want to declare each image's interval in its metadata, or already hold a `value_range` key there | additive (experimental) |
| [Frame statistics](#frame-statistics) | want the time between frames, or the frames that repeat the one before them, as factors of a tracking dataset | additive (experimental) |
| [Repeated track ids](#a-track-id-given-to-two-detections-in-one-frame) | give a tracking dataset a target that carries one track id on two detections of one frame, or pass `track_stats` a `Track` whose `frame_indices` do not strictly increase | **now raises** |
| [Track gap and heading](#track-gap-and-heading) | want the longest gap in a track, or the direction of its net movement, as factors of a tracking dataset | additive |

If none applies, your code needs no change.

## Blur statistics

{class}`.ImageStats` has two new flags, `VISUAL_BLUR` and `VISUAL_BLUR_DIRECTIONALITY`, in the new group
`ImageStats.BLUR`. They add the columns `blur` and `blur_directionality`. {class}`.VideoStats` has one new flag,
`BLUR_LEVEL`, in the new group `VideoStats.BLUR`. It adds the column `blur_level`, and {func}`.video_stats` has a new
keyword, `blur_samples`. See [Blur statistics](../concepts/BlurStatistics.md) for what the values mean and what they
cannot tell you.

```python
from dataeval.core import image_stats
from dataeval.flags import ImageStats

stats = image_stats(images, stats=ImageStats.BLUR)
```

`ImageStats.ALL` now includes the blur flags, and `VISUAL`, `VISUAL_BASIC` and `NO_HASH` do not. The default of
{func}`.image_stats` is what `ALL` was in v1.2 and the new `saturation` column (see the
[saturation statistic](#saturation-statistic)), so a call that passes no `stats` returns what it returned in v1.2 with that
one column added. A
request for `ALL`, or for a complement such as `~ImageStats.HASH`, now measures blur. It costs much more than
`sharpness`: on one machine a 3840x2160 frame took over a second, and nothing caps the size of an image. `ALL` holds
every statistic of a release, the [spatial statistics](#spatial-statistics) too, so a later release can add to it again.
A per-target request for `ALL` on a dataset now reads the dataset's labels, since two of the spatial statistics compare
classes, so it can raise on malformed labels where v1.2 never read them.
{class}`.Outliers` with `flags=ImageStats.ALL` now judges the blur statistics too. `ImageStats.STANDARD` is a new name
for the set `NO_HASH` names, and `NO_HASH` stays, so `ImageStats.NO_HASH` now prints, and its `.name` reads, as
`STANDARD`, and holds `saturation` like the default. `ImageStats.BASIC` is a new, smaller set that does not.

`VideoStats.ALL` now includes `BLUR_LEVEL`, so it adds one column, a second `ExperimentalWarning` and a longer run. So
does a complement such as `~VideoStats.PERSISTENCE`, and a complement that left out every statistic that needs OpenCV,
such as `~(VideoStats.EGO | VideoStats.PERSISTENCE)`, now needs it. The default of {func}`.video_stats` returns what it
returned in v1.2. It is the new `VideoStats.BASIC`, and `NO_EGO` stays as another name for the same set, so
`VideoStats.NO_EGO` now prints, and its `.name` reads, as `BASIC`. The way to the v1.2 `ALL` is
`VideoStats.ALL & ~VideoStats.BLUR`. The video statistic needs OpenCV, from the `dataeval[opencv]` extra, and measures
frames at a short side of 720 pixels at most. A blur request that measures videos at more than one short side raises
one `UserWarning`.

The blur statistics are experimental ⚠️. The first image request and the first video request in a process each raise
{class}`~dataeval.exceptions.ExperimentalWarning`, and the column names and values may change in a later release, and
for videos so may the `blur_samples` keyword. An evaluator that requests them, such as `Outliers`, raises the warning
attributed to a line inside the library. Filter it by category when you want to silence it.

## The view operations declare the blur, spatial and saturation statistics

The quality evaluators raise {class}`~dataeval.exceptions.StatsInvalidatedWarning` where a view operation's
declaration overlaps the statistics you asked for. A resize rescales a width in pixels, and a luminance mix changes
which picture is read, so v1.3 declares the blur statistics. An operation that clips a box, removes the boxes around
it or changes their classes changes the spatial statistics, and one that resizes or mixes channels moves the values that
sat at a saturation endpoint, so v1.3 declares those too:

| Operation | v1.2 declared | v1.3 declares |
| --- | --- | --- |
| {class}`.Resize`, in every mode | the dimension statistics except the channel count, and `sharpness`, with more under `mode="pad"` | the same, and `ImageStats.BLUR`, `ImageStats.SPATIAL` and `ImageStats.PIXEL_SATURATION` |
| {class}`.SelectChannels` with `"gray"` | the channel count, `PIXEL` and `VISUAL` | the same, and `ImageStats.BLUR` and `ImageStats.PIXEL_SATURATION` |
| {class}`.Crop` | the dimension statistics except the channel count and the bit depth | the same, and `ImageStats.SPATIAL` |
| {class}`.DetectionCrops` | the dimension statistics except the channel count | the same, and `ImageStats.PIXEL_SATURATION` |
| {class}`.Filter` and {class}`.ClassFilter`, unless `drop="items"` | nothing | `ImageStats.SPATIAL` |
| {class}`.Indices` with `exclude=True` and addresses of rows inside items | nothing | `ImageStats.SPATIAL` |
| {class}`.Relabel` | nothing | `ImageStats.SPATIAL` with the default `on_unmatched="drop"`, and the two class statistics with either value |
| {class}`.TorchvisionTransform` | `ImageStats.ALL` | `ImageStats.ALL`, which now holds `BLUR`, `SPATIAL` and `PIXEL_SATURATION` |

A request without a blur, spatial or saturation flag gets the same warnings as before. `ImageStats.PIXEL` holds
saturation, so a request for it, and the default flags of {class}`.Outliers`, now warn for `saturation` through a
{class}`.Resize` or a {class}`.DetectionCrops`. An {class}`.Operation` of your own that names a group narrower than
`ALL`, such as `ImageStats.VISUAL`, covers none of them, so a request for `ImageStats.BLUR`, `ImageStats.SPATIAL` or
`ImageStats.PIXEL_SATURATION` raises no warning for it.

## Spatial statistics

{class}`.ImageStats` has five new flags in the new group `ImageStats.SPATIAL`. Each compares a box with the other
boxes of its image or with the image's edges: how far its nearest neighbor is, how much of it lies inside the image, how
much the other boxes cover, and how much it overlaps a box of the same class and a box of another. They need boxes, so
they are NaN on an image's own row, and they report `spatial_status` and further facts about each row in the result's
`details`; the {class}`.ImageStats` docstring defines each. They are stable and raise no
{class}`~dataeval.exceptions.ExperimentalWarning`, though a request for `ImageStats.ALL` still raises it for blur.

`ImageStats.ALL` holds them, as it holds blur, and so does a complement such as `~ImageStats.HASH`. A request for
nothing but spatial statistics raises `ValueError` where there are no box rows. A request that adds other statistics
returns NaN columns and warns once, unless it holds every other statistic of `ImageStats.ALL`: that request asks for
everything, so the statistics that cannot be measured read NaN without a warning, and a call with no boxes, or with
`per_target=False`, stays quiet under `ImageStats.ALL`. `ImageStats.ALL & ~ImageStats.SPATIAL` leaves them out. Where
there are boxes, each box is compared with every other box of its image, so the time grows with the square of the boxes
in one image: time a sample of your data before a long run.
{class}`.Outliers` with `flags=ImageStats.ALL` judges the spatial columns on a per-target call, and judges none on its
default per-image path. Its default threshold can sit above the largest value a column can take, and then it flags
nothing: a column that runs only from 0 to 1 and is mostly 0, such as `max_iou_other_class`, can get an upper bound
above 1. Set a threshold for the column to flag its large values, such as
`outlier_threshold={"max_iou_other_class": ConstantThreshold(upper=0.5)}`.

The two class statistics, `SPATIAL_MAX_IOU_SAME_CLASS` and `SPATIAL_MAX_IOU_OTHER_CLASS`, read class labels. A dataset
supplies them, and explicit boxes take them through `labels=`. Any negative id is a missing label, which covers the
ignore id a dataset uses, so a negative id cannot be a class. Where a missing label could hide the true largest overlap
the value is NaN with the reason `missing_labels`, and where `labels` is absent every label is missing, so those columns
read NaN where a box overlaps another and 0.0 where none does. A dataset's floating-point labels are read as class ids:
a whole number is the id, NaN is missing, and a fractional value raises `ValueError`. The covered fraction takes memory
that grows with the square of the number of boxes that overlap one box, so a box that more than 1,000 others overlap
reads NaN with the reason `too_many_overlaps`. That limit is provisional.

## Saturation statistic

{class}`.ImageStats` has a new flag, `SATURATION` (the member is named `PIXEL_SATURATION`), in `ImageStats.PIXEL`. It
adds the column `saturation`, the share of finite raw values at a clipping endpoint, and reports `saturation_status` and
four more values in the result's `details`; the {class}`.ImageStats` docstring says what each holds. {func}`.image_stats`
has one new keyword, `saturation_atol`. The endpoint is the upper bound of the declared `value_range`, then the maximum
of an unsigned integer dtype, and the column is NaN where none applies, as on float data.
[Saturation at a clipping endpoint](../concepts/ImageStatistics.md#saturation-at-a-clipping-endpoint) says what the number
can and cannot show. The statistic is stable.

`PIXEL` holds it, so `ImageStats.STANDARD`, `NO_HASH` and `ALL` do, and so do a complement such as `~ImageStats.HASH`, the
default of `image_stats` and the default flags of {class}`.Outliers`. Those requests gain a `saturation` column and its
details, and `Outliers` can judge it: an image with one clipped value among thousands can be flagged. The column is NaN
for float images that declare no range, and 12-bit data stored in `uint16` reads against 65535 until its range is
declared, as [Declared value ranges](#declared-value-ranges) describes. `ImageStats.BASIC` does not hold it, and
`(ImageStats.STANDARD | ImageStats.HASH) & ~ImageStats.PIXEL_SATURATION` is the v1.2 set.

## Declared value ranges

A dataset can declare the interval an image's values occupy, as a `(low, high)` pair under `value_range` in that datum's
metadata. {func}`.image_stats` reads it for each image, for every statistic that reads an interval (the histogram and
entropy, the visual statistics, blur, `DIMENSION_DEPTH` and saturation), so one collection can hold sensors of different
depths, and {class}`.Outliers` and {class}`.Duplicates` read it through {func}`.image_stats`. The `value_range=` argument
beats it, and a channel group's own range beats both. An iterable of arrays has no metadata.

The metadata key is experimental ⚠️. The first declaration read in a process raises
{class}`~dataeval.exceptions.ExperimentalWarning`, and the key and the shape of its value may change in a later release.
It is a claim about the pixels, so a {class}`.TorchvisionTransform` that rescales an image drops it from that datum, and
{class}`.Metadata` does not read it as a factor. A dataset that already holds a `value_range` key with another meaning
now has it read, and a pair that is not finite and ordered raises when a statistic that reads an interval is requested.

A declared range that the values leave is now logged for every statistic that reads it, naming the images, where only
the histogram said so. The `value_range=` argument of {func}`.image_stats` is stable.

`DIMENSION_DEPTH` now reads a depth from a declared range of `(0, 2**n - 1)` on integer data, where it reported NaN for
any declaration, so a call with `value_range=(0, 4095)` on `uint16` data reports 12.

## Near-duplicate video segments

{func}`.hash_neighbors` has two new arguments, `partition` and `k`, and {class}`.Duplicates` has a new option,
`segment_neighbors`. All three are experimental ⚠️ and raise {class}`~dataeval.exceptions.ExperimentalWarning` once per
process. `Duplicates` raises it where `segment_neighbors` is set, and not for the `partition` and `k` it passes itself.

The segment search for video now passes `partition`, which reports only the pairs whose two labels differ, so it no
longer enumerates a pair inside one sequence. A video with a long static stretch holds quadratically many identical
frames, and two such videos used to exceed the pair budget, `max_pairs`, so the pair lost its segments, including a
stretch the two videos truly share. Those pairs are now searched and can yield segments. A pair of videos that fit the
budget before returns the same pairs and distances. When the pairs crossing between two videos still exceed the budget,
the pair still loses its segments, and the log line for that moves from INFO to WARNING and names `segment_neighbors`.

`k` and `segment_neighbors` keep only each frame's `k` nearest matches, so that videos whose crossing pairs are still
quadratic can be searched. `None`, the default, leaves every result as before. A frame with a match still has one, but
a segment's extent and boundaries can shrink or move. 10 is a provisional starting point, chosen on simulated static
runs. The repr and the config of a `Duplicates` gain a `segment_neighbors` entry, `None` unless set.

## `image_stats` refuses boxes that are not four numbers and takes labels

An entry of `boxes=` that was a row of the wrong length was logged and measured as the box `(0, 0, 0, 0)`, which counts
as an invalid box. An entry that was a single number, such as one flat box `(x0, y0, x1, y1)` passed where a list of
boxes belongs, was measured as the full-image box without a message. A dataset target whose `boxes` had more than four
columns kept the first four and dropped the rest. {func}`.image_stats`, the deprecated `compute_stats` alias and
{func}`.unzip_dataset` now raise `ValueError` for all three, naming the image and the box:

```python
image_stats(images, boxes=[[(0, 0, 10)]])
# v1.2: logged, and measured as the box (0, 0, 0, 0)
# v1.3: ValueError: image 0, box 0: expected 4 values (x0, y0, x1, y1), got 3 values; ...
```

Give every box four numbers, and pass class ids through `labels=` instead of a fifth column. A box that still held NaN or
an infinity after conversion, such as `(nan, 0, 10, 10)` or `(0, 0, inf, 10)`, raised `ValueError` or `OverflowError`
from inside the library. It is now measured as the box `(0, 0, 0, 0)`, so `invalid_box` is True for it and
`invalid_box_count` counts it. A NaN in the second corner, such as `(0, 0, 10, nan)`, never raised and is unchanged: it
is measured as a box of zero height.

{func}`.image_stats` has a new keyword, `labels=`: one sequence of integer class ids per image, one id per box in that
image's `boxes` entry. It requires `boxes=` and raises where the lengths differ. The two class statistics of
`ImageStats.SPATIAL` read it and no other statistic does, so it changes no other result. It is experimental ⚠️: the
keyword may change, and it raises no warning.

## Frame statistics

{func}`.frame_stats` measures, for each frame of a video, the seconds since the previous frame (`elapsed_time_s`) and
whether the frame is identical to it (`repeat_frame`). `FrameStats.TIMING` reads timestamps only. The result attaches to
a tracking dataset with {meth}`.Metadata.add_factors`, which also adds the sequence roll-ups `elapsed_time_s_median`,
`elapsed_time_s_std` and `repeat_frame_fraction`. It is experimental and raises
{class}`~dataeval.exceptions.ExperimentalWarning` on the first call in a process. No existing call changes.

---

## Track gap and heading

{func}`.track_stats` adds two columns to every result: `max_gap_length`, the longest run of frames in which a track is
absent between two of its observations, and `net_heading_rad`, the direction in radians from a track's first to its last
box center. A heading of 0 points right, and a positive angle turns clockwise on the image. Read a heading only where
`net_displacement` is large, since where a track barely moved the heading is set by box jitter.

```python
result = track_stats(dataset)
metadata.add_factors(result, level="track", key="track_id")
```

No existing column changes. Attaching the result now brings two more track factors, and code that lists a result's
columns sees two more.

---

## A track id given to two detections in one frame

A tracker gives each id to one object per frame. A target that gave one id to two detections of a frame was accepted:
{class}`.Metadata` and {func}`.build_tracks` made a track with two boxes in one frame, and {func}`.track_stats` returned
an infinite `mean_speed` for it, from a step of zero frames. They now raise `ValueError`, naming the id and the frame,
as does `track_stats` for a hand-built `Track` whose `frame_indices` do not strictly increase. An id of `-1` marks a
detection no tracker linked and may repeat. The VisDrone2019-MOT validation split, 118,127 detections in 2,846 frames,
holds no frame with a repeated id.

## What to do

1. Name `ImageStats.BASIC`, `ImageStats.STANDARD` or `VideoStats.BASIC`, or single statistics, where your code needs
   columns that do not change between releases. Where you pass `ImageStats.ALL` and want the v1.2 columns, pass
   `(ImageStats.STANDARD | ImageStats.HASH) & ~ImageStats.PIXEL_SATURATION`, and intersect a complement `~X` with the
   same set. For videos, pass `VideoStats.ALL & ~VideoStats.BLUR`, and add `& ~VideoStats.BLUR` to a complement.
2. To measure blur, request `ImageStats.BLUR`, expect the `ExperimentalWarning`, and compare values only between images
   of one resolution.
3. To measure the blur of a video, request `VideoStats.BLUR`, expect the `ExperimentalWarning`, and compare values only
   between videos of one frame size.
4. Add `| ImageStats.BLUR` to the `invalidates` of your own `Operation` if it changes the picture and does not declare
   `ImageStats.ALL`, `| ImageStats.SPATIAL` if it clips, moves, removes or relabels boxes, and
   `| ImageStats.PIXEL_SATURATION` if it resizes or mixes channels.
5. If the log says a pair of videos lost its segments to the pair budget, set `Duplicates(segment_neighbors=10)`, expect
   the `ExperimentalWarning`, and check the segments it then reports, since a cap can move their boundaries.
6. Give every box in `boxes=`, and in a dataset's targets, four numbers, and pass class ids through `labels=`.
7. To find isolated, overlapped or frame-truncated targets, request `ImageStats.SPATIAL` with boxes, `labels=` and
   `per_image=False`, and expect the `ExperimentalWarning`.
8. To measure how much of an image sits at a clipping endpoint, request `ImageStats.PIXEL_SATURATION`, and declare
   `value_range` as `(0, 4095)` in the datum metadata for 12-bit data stored in `uint16`.
9. Where a tracking dataset raises for a repeated track id, give the extra detections ids of their own, or `-1` to leave
   them untracked.
