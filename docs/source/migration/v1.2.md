# Migrating from v1.1 to v1.2

v1.2 removes features deprecated in v1.1. It also updates {class}`.SourceIndex` into an address that names one row at
one level.

v1.1 reorganized metadata addressing, dataset transformations, and image statistics scaling. Each change retained a
deprecated interface that emitted a warning pointing to its replacement. v1.2 removes those deprecated interfaces.

To identify code that requires updates, run your v1.1 pipeline with warnings promoted to errors:

```bash
python -W error::DeprecationWarning your_script.py
```

This flags `SourceIndex.target`, which is newly deprecated in v1.2 and emits a warning. It does not flag the removals
listed below, because those raise exceptions directly. Check for those removals by name. `ClassFilter`,
`compute_ratios`, `compute_stats`, and two uses of `label_parity` (passing `num_classes`, or giving neither groups nor
`assume_independent=True`) are also newly deprecated, but they warn with a `FutureWarning`, so add
`-W error::FutureWarning` to find them.

## Metadata levels

v1.1 deprecated legacy image and target attributes with warnings. Those attributes are now removed. Use the following
replacements:

| Removed in v1.2 | Use |
| --- | --- |
| `md.image_data` | `md.rows_at(md.item_level)` |
| `md.target_data` | `md.rows_at(md.label_level)` |
| `md.raw_data` | `md.rows_at(md.view).select(md.factor_names).to_numpy()` |
| `md.target_factors_only` | `md.at(level)` to choose rows, `md.inherited` to choose whether ancestor factors count |
| `md.get_image_factors(i)` | `md.rows_at("unit").filter(pl.col("item_index") == i)` |
| `md.get_target_factors(i, t)` | `md.rows_at(md.label_level).filter((pl.col("item_index") == i) & (pl.col("target_index") == t))` |
| `md.has_targets()` | `md.multi_target` |
| `md.filter_by_factor_type(t)` | `md.filter_by_factor(lambda _, fi: fi.factor_type == t)` |

Two factor behaviors are also removed. The argument `level="combined"` was the v1.1 name for an array ordered by `(item,
target)`. It is no longer accepted. In addition, {meth}`.Metadata.add_factors` no longer infers a level from factor
length. Every `add_factors` call must pass `level=` or `source_index=`. Omitting both raises `ValueError`.

## Filter replaces ClassFilter

{class}`.Filter` keeps a dataset's items, and the detections and tracks inside them, by class and by metadata factor.
`ClassFilter` is deprecated and will be removed in v2.0. It warns with `DeprecatedWarning`, a `FutureWarning`, so
`-W error::DeprecationWarning` does not flag it; run with `-W error::FutureWarning` to find it. A filter that keeps
nothing now warns with a `UserWarning`, which `ClassFilter` never did.

| v1.1 | v1.2 |
| --- | --- |
| `ClassFilter([0, 2])` | `Filter(classes=[0, 2])` |
| `ClassFilter([0, 2], filter_detections=False)` | `Filter(classes=[0, 2], drop="items")` |
| `ClassFilter([])` | remove the operation; `Filter` refuses an empty `classes` |

Class labels must be integers, numpy integers included. `ClassFilter` used to accept integral floats such as `0.0`, and
now raises `TypeError` for them, as `Filter` does.

New with `Filter`:

- **Factor predicates**, as SQL or a polars expression: `Filter("time_of_day = 'night' AND altitude > 100")`. A string
  predicate is what a configuration file can hold.
- **Cleaning without dropping images**: `Filter("occlusion < 0.5", drop="detections")` keeps every image and removes
  the detections that do not match.
- **Multi-object tracking**: class and factor filtering on tracking datasets, removing detections or whole tracks;
  `ClassFilter` raised `TypeError` there.

## The per-channel row path is removed

In v1.1, `compute_stats(per_channel=True)` returned one row per channel, addressed by a third field on
{class}`.SourceIndex`. That field is removed. The `per_channel` argument, the `channels=True` alias, and the
`channel_index` column in {class}`.Outliers` are also removed.

To extract channel statistics, specify band names to produce columns:

```python
compute_stats(images, per_channel=True)  # v1.1, deprecated
image_stats(images, channels={"r": 0, "g": 1, "b": 2})  # v1.2
```

Band groups produce factor columns rather than separate rows. Channels do not correspond to a metadata level, so
per-channel rows could not be stored in {class}`.Metadata`. Consequently, evaluators such as balance, diversity, and
parity could not process them. Factor columns such as `nir_mean` are stored in metadata and evaluated directly.

**`per_channel=False` is also removed.** Because the parameter itself is removed, passing any value raises `TypeError`.
v1.1 warned only when `per_channel` was truthy. Remove `per_channel` wherever it appears, including calls that passed
the default `False`:

```python
compute_stats(images, stats=ImageStats.PIXEL, per_channel=False)  # v1.1
image_stats(images, stats=ImageStats.PIXEL)  # v1.2
```

**{class}`.Outliers` no longer emits `channel_index`.** That column was populated only by per-channel rows. Band groups
are thresholded independently per column. Previously, per-channel rows used a single pooled threshold across every band
of every image.

**{func}`.compute_ratios` matches on item index alone.** Previously, it paired each bounding box row with the image row
sharing `(item, channel)`. Channel indices are removed, so rows are matched by item index. The validation check
requiring matching `per_channel` settings between inputs is also removed.

## `SourceIndex` is an address

{class}`.SourceIndex` retains three fields. The third field is now `level`, which specifies the metadata level addressed
by the second field (`key`). A single tuple can now name a row at any level in a dataset's level graph, rather than only
an item and its bounding boxes.

```python
SourceIndex(item, target, channel)  # v1.1
SourceIndex(item, key, level)  # v1.2
```

**`target` is renamed to `key`.** Each level identifies rows by a specific column. `key` holds that column's value, such
as `target_index` for an instance, `unit_index` for a video frame, or `track_id` for a track. Accessing `target` or
passing `target=` to the constructor still works but emits a `DeprecationWarning`. The `target` attribute and parameter
will be removed in v1.3.0.

```python
si.target  # v1.2: works, warns
si.key  # v1.2

SourceIndex(item=3, target=7)  # v1.2: works, warns
SourceIndex(item=3, key=7)  # v1.2
```

**Positional construction and unpacking still take three values, but the third value is now a level name.** Unpacking
`source_index[0]` binds `(item, key, level)`. Positional construction validates the level name. For example,
`SourceIndex(0, 1, 2)` raises `ValueError` ("level=2 is not a level") because `2` is not a valid level name.

```python
item, target, channel = source_index[0]  # v1.1
item, key, level = source_index[0]  # v1.2

SourceIndex(0, 1, 2)  # v1.2: ValueError, "level=2 is not a level"
```

Available levels depend on the dataset. An address naming a level absent from your data is caught when the address is
used, rather than when it is built.

**The string representation retains up to three parts.** `str(si)` produces `"3"`, `"3/7"`, or `"3/12/unit"`.
`SourceIndex.from_string` accepts those formats, as well as `"3/-/sequence"` for a level stated without a key. The third
part must be one of `sequence`, `unit`, `track`, or `instance`. Any other value is rejected. In v1.1, that segment was
read as a channel number.

**Leave the level unstated unless addressing `unit` or `track`.** An unstated level resolves to the item level when key
is omitted, or to the label level when key is provided. `SourceIndex(3)` addresses an item. `SourceIndex(3, 7)`
addresses a label. Specify a level explicitly only when addressing intermediate levels such as `unit` or `track`.

Address equality and hashing depend on exact representation. `SourceIndex(3, 7)` and `SourceIndex(3, 7, "instance")` are
not equal and have different hash values. They act as distinct keys in dictionary results returned by {class}`.Outliers`
and {class}`.Duplicates`. {func}`.image_stats` emits the minimal form without an explicit level.

### Addressing arbitrary metadata levels

{meth}`.Metadata.add_factors` accepts addresses at any metadata level. Per-frame or per-track measurements can be
attached as individual values instead of entire keyed columns:

```python
md.add_factors({"speed": [...]}, source_index=[SourceIndex(0, 5, "track"), ...])
```

This matches the column-oriented contract of `add_factors(level=..., key=...)`. The address consists of `(item_index,
key)` and the level name. See [](../concepts/MetadataLevels.md#naming-a-row-keys-or-addresses).

An address identifies a row, but does not specify hierarchical containment. For example, a source index does not
indicate which frame contains a detection. Consequently, {meth}`.Metadata.from_factors` given addresses builds only the
two-level structure. To preserve full hierarchy, construct {class}`.Metadata` from the dataset first, then add factors.

### Unchanged functionality

The `channels=` mapping, `value_range`, `normalize_pixel_values`, `per_image`, `per_target`, and `per_background`
parameters remain unchanged. Computed statistic values are also unchanged. Calls that omitted `per_channel` in v1.1
return the same results in v1.2.

## Evaluators report at the level they detected at

{class}`.Outliers` and {class}`.Duplicates` read the level directly from each address rather than inferring it from
missing fields. Both evaluators return the input addresses in their results.

**Image dataset results are unchanged.** For image datasets, {func}`.image_stats` emits addresses without an explicit
level. Output columns and values remain identical to v1.1. The changes below apply only when a statistic source index
specifies an explicit level.

**Both evaluators add a level column.** `Outliers` results add a `level` column, and `Duplicates` results add an
`address_levels` column. These columns distinguish rows that share key indices, such as video frames and tracks. When
all findings occur at either the item level or the label level, as in image datasets, these columns are omitted. In
`Duplicates`, the existing `level` column is retained with values `"item"` and `"target"`. That column indicates the
detection role of a group, while `address_levels` indicates the metadata level of each member.

**Findings normalize addresses to canonical form.** Evaluators return canonical addresses rather than echoing input
formats verbatim. For example, `SourceIndex(3, 7, "instance")` normalizes to `SourceIndex(3, 7)`. `SourceIndex(3, None,
"sequence")` normalizes to item index `3`. An item has one root row, and a key indicates a label row. Normalization
ensures that runs over equivalent addresses produce identical results.

**Evaluators partition statistics by metadata level.** `Outliers` fits a separate threshold distribution for each
metadata level. Per-frame statistics are evaluated only against other per-frame statistics, rather than across
per-sequence statistics. `Duplicates` partitions candidates by level before hashing. This prevents comparisons across
different metadata levels.

**`per_image` and `per_target` filter item and label levels regardless of address format.** Equivalent addresses are
filtered identically. `SourceIndex(3, 7)` and `SourceIndex(3, 7, "instance")` are filtered identically, as are
`SourceIndex(3)` and `SourceIndex(3, None, "sequence")`. Intermediate levels, such as video frames or tracks, are
unaffected by these flags and are always included. Result accessors for intermediate levels use {class}`.SourceIndex`
keys, because integer item indices cannot identify those rows.

Evaluator output addresses can be passed directly to {meth}`.Metadata.add_factors`:

```python
outliers = Outliers().from_stats(frame_stats)
md.add_factors(
    {"is_outlier": [address in outliers.outliers for address in addresses]},
    source_index=addresses,
)
```

## `discrete_features`

The `discrete_features` parameter was updated across mutual information functions.

- In {func}`.mutual_info`, `discrete_features` is now **required**. Omitting it raises `TypeError`. In v1.1, omitting it
  triggered auto-detection and emitted a warning. Pass `discrete_features=[not b for b in md.is_binned]`.
- In {func}`.mutual_info_classwise`, the `discrete_features` parameter is **removed**. Passing it raises `TypeError`.
  The parameter previously had no effect and was discarded downstream.

{class}`.Balance` is unaffected. It always passed the value explicitly.

## The `score` column is one confidence per row

In MAITE, a target can provide scores per bounding box (`(N,)`) or per class for each box (`(N, CLASSES)`). A
classification target is a score vector. In v1.1, metadata stored target scores directly in the dataframe. The `score`
column was `Array(Float32, n_classes)` for multi-class targets and `Float32` for single-score targets. Because column
width depended on class count, datasets with different vocabularies could not be concatenated into a single dataframe.
In those cases, {func}`.merge_datasets` raised an error from `np.concatenate`.

The `score` column is now always `Float32`. It stores the confidence of a row for its assigned class, extracted from
whichever layout the target provides. Rows without scores contain **null**. To access per-class probabilities, read them
from the target rather than `md.dataframe["score"].to_numpy()`. {class}`.SourceLocator` retrieves individual detections.
{class}`.ScoresExtractor` extracts per-class prediction arrays from model outputs.

{class}`.Relabel` aligns score arrays when transforming labels. Per-class arrays are indexed by their original
vocabulary. In v1.1, relabeled detections retained source-indexed score columns alongside relabeled targets.
Consequently, scores mapped to incorrect classes or exceeded array bounds. Detection scores are now reduced to a single
confidence value for the source label before vocabulary transformation. Classification vectors are mapped into the
target vocabulary, summing probabilities when classes are merged. A `Mapping[int, str]` target vocabulary must use
non-negative integer indices. Non-contiguous class indices are supported and no longer raise `IndexError`.

If code accesses `dataset[i][1].scores` from a relabeled detection dataset and requires per-class arrays during
migration, pass `Relabel(..., reduce_detection_scores=False)`. This maps scores into the target vocabulary. In v1.1, the
array retained the source vocabulary indexing and width. Verify any code that indexes the resulting array. Classes
missing from the source array receive a score of `0.0` rather than being treated as absent. Merged classes combine their
scores by summation.

Setting `reduce_detection_scores=False` does not change the metadata `score` column width. The column retains one value
per row under both settings. However, it changes the numeric values in that column because metadata reads from the
transformed target. When classes are merged, the column reflects the summed class score. Where scores cannot be read,
the column contains `0.0` instead of `null`. The `reduce_detection_scores` parameter emits a warning and will be removed
in v1.3. Omitting the parameter uses the default reduction behavior.

## A class axis of your own

{meth}`.Metadata.classed_by` configures one or more factors as the class axis. Unmodified metadata instances continue to
report default class labels.

```python
by_weather = metadata.classed_by("weather")
Balance().evaluate(by_weather)  # conditions on weather
Coverage().evaluate(by_weather, embeddings=emb)  # per-weather coverage
split_dataset(by_weather, stratify=True)  # folds balanced over weather
```

This configuration introduces three behaviors:

**Original dataset labels become a factor.** The pivoted metadata gains a factor named `class` containing the original
labels. Results retain the relationship between the custom axis and the original dataset labels.

**All class-label consumers use the pivoted axis.** {attr}`.Metadata.class_labels` and {attr}`.Metadata.index2label`
update together. Evaluators without an explicit `label=` parameter evaluate against the pivoted axis.
{class}`.Representation` is an exception because it validates label names against an ontology. It raises an error when
passed pivoted metadata.

**Results record the active class axis.** Class-conditional outputs add a `class_axis` field holding a
{class}`.ClassAxis`. The `meta().state` mapping adds `class_axis`, `class_axis_source`, and `class_axis_level` entries:

```python
result = Balance().evaluate(by_weather)
result.class_axis.source  # "derived" (custom axis rather than dataset labels)
result.class_axis.rows_per_group_entity  # 3.0 if a per-image axis was read from detections
```

For standard evaluations, `class_axis_source` records `"ground_truth"`. In previous releases, this field recorded the
string `"NoneType"`. When setting `label=` on bias evaluators, `class_axis_source` is recorded identically.

The class axis configuration persists across `at`, `where`, `having`, and `agg` operations. Like `view`, `include`, and
`exclude`, it is omitted during serialization with {meth}`.Metadata.save`.

See [](../notebooks/tt_analyze_by_custom_class_axis.py) for a worked example covering composite axes and metadata level
selection.

## Duplicates checks annotation and metadata factors

{class}`.Duplicates` now evaluates annotations and optional metadata factors alongside pixel checks. Datasets without
targets or `duplicate_factors` produce the same pixel-only results as v1.1.

**Datasets with targets include annotation duplicate rows.** When a dataset yields `(image, target, metadata)` and
targets contain `boxes` or `labels`, `Duplicates.evaluate` inspects annotations by default. Two additional result
patterns can appear:

- Groups whose `methods` list contains `"annotation"`. These represent items sharing identical annotations regardless of
  pixel similarity.
- Existing pixel groups (`dup_type="exact"` or `"near"`) where `differs_on` contains `"annotation"`. These represent
  matching images with differing annotations.

These additions do not replace previous findings. They provide new rows or additional fields on existing rows.

**Results add two columns: `differs_on` and `annotation_divergence`.** `differs_on` (`list[str] | None`) uses a
three-state representation. A `null` value indicates the axis was not evaluated. An empty list `[]` indicates the axis
was evaluated and values agreed. A populated list names the attributes that disagreed. `annotation_divergence` (`float |
None`) records divergence scores. See [Reading `differs_on` and the divergence
columns](../concepts/ActingOnResults.md#duplicates-and-near-duplicates) for the complete three-state contract and pair
row `mean_iou` behavior.

**Metadata factor grouping requires explicit configuration.** Passing `metadata=` and `duplicate_factors=[...]` to
`evaluate()` groups items whose specified factor values match exactly. These groups are reported with
`dup_type="factors"`. Omitting `duplicate_factors` disables factor grouping. No factors are evaluated by default.

**Every named factor must agree.** `duplicate_factors` functions as a conjunction. Items are grouped only when all
named factors match; matching some and differing on one produces no group. Adding factors narrows matches. Items
with unstated factors (null or NaN) are excluded from grouping. `factor_cardinality` counts stated values only.

**`evaluate()` accepts a `Metadata` instance directly.** When evaluating metadata alone, no pixels or annotations
are decoded, so `duplicate_factors` is required. The run reports at `level="item"` only.

```python
# Unchanged from v1.1: image datasets without targets produce identical results
Duplicates().evaluate(images)

# New in v1.2: object detection datasets include annotation duplicate rows
Duplicates().evaluate(od_dataset)

# New in v1.2: optional grouping by specified metadata factors
Duplicates().evaluate(od_dataset, metadata=Metadata(od_dataset), duplicate_factors=["capture_id"])

# New in v1.2: all specified factors must agree
Duplicates().evaluate(od_dataset, metadata=Metadata(od_dataset), duplicate_factors=["capture_id", "camera_id"])

# New in v1.2: evaluate metadata directly without decoding images
Duplicates().evaluate(Metadata(od_dataset), duplicate_factors=["capture_id"])
```

**Existing group types are preserved.** The evaluator continues to report `exact`, `near`, and video group types
(`segment`, `aligned`, and `redundant`) as in previous releases.

## Removing what an evaluator flagged

`DuplicatesOutput.deduplicate()` and `OutliersOutput.prune()` return a {class}`.RemovalPlan`: the
{class}`.SourceIndex` addresses of the rows to remove. Pass it to {class}`.Indices` with `exclude=True`.

```python
plan = Duplicates().evaluate(dataset).deduplicate() | Outliers().evaluate(dataset).prune()
cleaned = View(dataset, Indices(plan, exclude=True))
```

`Indices` accepts addresses as well as ints. With `exclude=True`, it removes a detection named by its `target_index`
and, on a tracking dataset, a whole track named by its `track_id`. Every image and frame stays, even when all of its
detections are removed.

Build the view on the dataset the evaluators read. A plan names positions in that dataset, and they are renumbered
once anything is removed.

## Evaluators take precomputed inputs

Each evaluator family now has a method per kind of input you may already hold, beside `evaluate`, which still accepts
everything it did. `evaluate` converts its argument and calls the method, so both give the same result.

| Evaluator | Method | Takes |
| --- | --- | --- |
| `Balance`, `Diversity`, `Parity` | `from_metadata(metadata)` | a `Metadata`, or any metadata container |
| `Representation` | `from_labels(labels, index2label=None)` | any container with `class_labels` |
| `Coverage`, `Prioritize` | `from_embeddings(embeddings, labels=None)` | an embeddings array, and optionally one label per embedding |
| `DriftUnivariate`, `DriftMMD`, `DriftKNeighbors`, `DriftDomainClassifier` | `from_embeddings(reference, data)` | reference and test embeddings: `fit(reference).predict(data)` in one call |
| `DriftWasserstein` | `from_embeddings(reference, validation, data)` | the validation set `fit` requires, between them |
| `ChunkedDrift` | `from_embeddings(*embeddings)` | the arrays its detector's `from_embeddings` takes |
| `OODKNeighbors`, `OODDomainClassifier` | `from_embeddings(reference, data)` | reference and test embeddings, and `predict`'s keywords |

Build the metadata or embeddings once and share them:

```python
metadata = Metadata(dataset)
balance = Balance().from_metadata(metadata)
parity = Parity().from_metadata(metadata)
```

The drift and OOD detectors keep `fit` and `predict` for fitting once and testing several datasets. The reconstruction
detectors have no `from_embeddings`: their model reads whatever array it was trained on, usually images.

`Coverage.from_embeddings` without labels runs every item as one class, `0`. `Coverage` and `Prioritize` refuse
labels that do not hold one entry per embedding, such as a detection dataset's labels, which hold one per target. For
`Prioritize.evaluate` this is new: v1.1 accepted mismatched `class_labels` without complaint.

## Constructor arguments are validated

In v1.1 an evaluator validated its `Config` only when you built the `Config` yourself. Arguments passed to the
constructor were stored unchecked, so `Diversity(method="nope")` or `Balance(num_neighbors="abc")` succeeded and
failed later, or not at all. v1.2 validates constructor arguments the same way, and raises a pydantic
`ValidationError`, which is a `ValueError`, naming the field.

Numeric settings are also checked against the range they are meaningful in: counts above zero, p-value thresholds
in (0, 1), shares and scores in [0, 1], and percentiles in [0, 100]. The ranges appear in each `Config`'s JSON Schema.

```python
Diversity(method="nope")  # v1.1: accepted; v1.2: ValidationError naming `method`
Balance(config=Balance.Config(label="weather"), num_neighbors=7)  # unchanged
```

## Drift and OOD configs are validated

The `Config` of every drift and OOD detector is now a pydantic model, as every other evaluator's is. A wrong type or
an unknown choice fails when the `Config` or the detector is built, naming the field, rather than later in `fit` or
`predict`. The error is a pydantic `ValidationError`, which is a `ValueError`.

Build a `Config` with keywords, and use the pydantic methods in place of the `dataclasses` helpers:

| v1.1 | v1.2 |
| --- | --- |
| `DriftUnivariate.Config("ks", 0.05)` | `DriftUnivariate.Config(method="ks", p_val=0.05)` |
| `dataclasses.replace(config, p_val=0.01)` | `config.model_copy(update={"p_val": 0.01})` |
| `dataclasses.asdict(config)` | `config.model_dump()` |
| `dataclasses.fields(config)` | `type(config).model_fields` |

## Outliers reads pixel statistics in stored units

`Outliers.evaluate` now measures `PIXEL` statistics in the units the data is stored in, as {func}`.image_stats` does
by default. In v1.1 it normalized pixel values to `[0, 1]` first, so `evaluate` and `from_stats` on statistics from
`compute_stats` could flag different images from the same data.

Every threshold except {class}`.ConstantThreshold` scales with the data, so for images stored at one bit depth **no
outlier flag moves**. Two cases change:

- A `ConstantThreshold` on a `PIXEL` statistic is now read in stored units. Rescale its bounds, for example from `0.8`
  to `204` for 8-bit data.
- Images stored at different bit depths are no longer put on one scale. To compare them the v1.1 way, compute the
  statistics normalized and pass them to `from_stats`:

```python
stats = image_stats(images, stats=ImageStats.PIXEL, normalize_pixel_values=True)
Outliers().from_stats(stats)
```

`VISUAL` statistics are unaffected: they always read the display range.

## Relative box geometry in the dimension statistics

`ImageStats.DIMENSION` now includes seven `rel_*` statistics: box offset, width, height and area as fractions of the
image, and distance to the image center and nearest edge as fractions of the half-diagonal and of that edge's
dimension. They carry exactly the definitions {func}`.compute_ratios` applies to the absolute statistics, and are
grouped as `ImageStats.DIMENSION_RELATIVE`. Existing statistics are unchanged.

Because `Outliers` computes `DIMENSION` by default, a run with `per_target=True` can report outliers on the `rel_*`
statistics too. An item's own row is the whole frame, so its relative values are constant and never flagged.

## `compute_ratios` is deprecated

{func}`.compute_ratios` is deprecated and will be removed in v1.3. It warns with `DeprecatedWarning`, a
`FutureWarning`. Both of its uses have a replacement that gives the same values:

- Box geometry relative to its image is a statistic now. Compute `ImageStats.DIMENSION_RELATIVE`, or the single
  `rel_*` flag you need, with `per_target=True`.
- For any other statistic, add the per-image and per-target statistics to a {class}`.Metadata`. Each box row at the
  `instance` level carries its image's value, so the ratio is one division.

| v1.1 | v1.2 |
| --- | --- |
| `compute_ratios(stats)["stats"]["size"]` | `image_stats(..., stats=ImageStats.DIMENSION_REL_SIZE, per_target=True)["stats"]["rel_size"]` |
| `compute_ratios(stats)["stats"]["brightness"]` | `md.add_factors(stats)`, then `md.rows_at("instance").select(pl.col("instance_brightness") / pl.col("unit_brightness"))` |

The `rel_*` statistics use the definitions `compute_ratios` applied to `offset_x`/`offset_y`, `width`, `height`,
`size`, `distance_center` and `distance_edge`. A custom `override_map` becomes a polars expression over the same
`instance_` and `unit_` columns.

## `compute_stats` is now `image_stats`

`compute_stats` is renamed to {func}`.image_stats`, which says what it measures now that video has its own statistics.
The parameters and the result are unchanged. The old name still works until v2.0 and emits a `DeprecatedWarning`.

```python
stats = compute_stats(images, stats=ImageStats.PIXEL)  # v1.1
stats = image_stats(images, stats=ImageStats.PIXEL)  # v1.2
```

Leaving `normalize_pixel_values` unset no longer emits a `FutureWarning`. Its default stays `False`, so results do not
change.

## Track statistics declare their labels and add a gap fraction

{func}`.track_stats` adds `gap_fraction`, the share of the frames a track spans in which it is absent. Its result also
declares `labels` categorical: `Metadata.add_factors` records the track labels as a vocabulary, as
`factor_levels=` would, so no consumer treats a class id as a quantity. A vocabulary you declared yourself is kept.

## `video_stats` describes each video

{func}`.video_stats` computes statistics that describe a video as a whole, one row per video, in one walk of each
video's frames. {class}`.VideoStats` selects them, in the groups `DESCRIPTIVE` (frame count, duration, frame rate),
`REDUNDANCY` (the share of frames that repeat the one before, and the longest such run) and `EGO` (camera motion
summaries, which need OpenCV from the `dataeval[opencv]` extra). The default is `VideoStats.NO_EGO`, everything that
does not need OpenCV.

```python
from dataeval.core import video_stats

metadata.add_factors(video_stats(dataset))  # one row per video, at the sequence level
```

To check measured values against ones the dataset already reports, such as `video_duration`, pass
`return_collisions=True` to {meth}`.Metadata.add_factors`. It returns the videos where the two disagree, within an
optional `collision_tolerance`.

`redundancy_radius` is the Hamming distance within which a frame counts as redundant, and shares its default with
{class}`.Duplicates`. `ego_gap` and `ego_proc_short_side` pass through to {func}`.ego_stats`, whose per-frame
measurements the `EGO` summaries reduce through the same roll-up `Metadata.add_factors` uses.
{func}`.ego_stats` now measures videos in parallel under `max_processes`, and accepts a list of streams. Set
`max_processes=1` for a dataset whose videos share one open decoder. To look inside one video instead, measure its
frames with {func}`.image_stats` over {class}`.SequenceFrames`. See
[Volatility and drift of a per-frame statistic](../concepts/MetadataLevels.md#volatility-and-drift-of-a-per-frame-statistic).
`SequenceFrames` can walk a video more than once, so each `dataset[i]` must return a stream that can be walked from its
first frame, independently of any earlier stream for the same index.

## `AddressedResult`

{class}`.AddressedResult` is the new base for a statistics result whose values carry an address, a `source_index` that
names the row of each value. {class}`.StatsResult` now extends it with its image bookkeeping (`object_count`,
`invalid_box_count` and `image_count`), so `image_stats` and `compute_ratios` return what they did before.
{func}`.video_stats` returns an `AddressedResult` directly, since a video has no image bookkeeping. Code that only
reads `stats` and `source_index` needs no change, and `combine_stats_results` now accepts any addressed result.

## Duplicates hashes the native pixel values

Perceptual hashes (`phash`, `dhash` and their `_d4` variants) read an image in the dtype it is stored in. Previously
{func}`.image_stats` converted every image to float64 first, and a float image with a maximum of at most 1 is read as
holding values in [0, 1] and stretched to full contrast. Integer images are now hashed at their stored values instead.
`xxhash` still digests the float64 view, so its values are unchanged.

{class}`.Duplicates` groups change only where integer images have a maximum of at most 1. Floating-point images, and
integer images with any larger value, hash exactly as before. The case to watch is a binary mask stored as 0 and 1.

- A 3-channel (RGB) mask, or one with 5 or more channels, now reads as black, because its Rec. 601 luma truncates to
  0. It hashes flat, so distinct masks group as near duplicates.
- A single-channel, 2-channel or 4-channel mask still hashes by its content, though to different values than before.

Scale masks to 0–255 before running {class}`.Duplicates`. That restores the earlier hashes. If you stored hashes of
such images, recompute them.

---

## Grayscale scales integer images deeper than 8 bits

{func}`.to_canonical_grayscale` clipped every value above 255, so 12- and 16-bit integer images, such as 14-bit infrared
in `uint16`, mostly saturated to a flat white frame. Their perceptual hashes then matched each other, and ego motion
read them as a still camera. Such an image is now scaled from the encoding {func}`.get_value_range` decodes for it:

- a maximum up to 4095 scales from 12 bits;
- a maximum up to 65535 scales from 16 bits.

Only integer images with a value above 255 are affected. Their `phash` and `dhash` values change, and so do
{class}`.Duplicates` groups, `ego_stats`, `video_stats` and BoVW features that read them. 8-bit images, signed images
and float images convert exactly as before. If you stored hashes of deeper integer images, recompute them.

## Re-detecting from statistics honors per_image and per_target

`Outliers.from_stats` defaults to `per_target=False`, while `image_stats` defaults to `per_target=True`, so the
default call `Outliers().from_stats(image_stats(dataset))` reports item rows only. Its `with_threshold`, `classwise`
and `itemwise` re-detected from every row of the statistics, so they returned target rows that the first result did not
report. Re-detection now covers the rows the flags selected, so a result and its re-detections describe the same rows.
A result built with `per_image=False` likewise no longer gains item rows when you re-detect. Rows addressed at a level
between an item and its labels, such as a frame or a track, are still always included.

To keep target rows in the result and in its re-detections, pass `per_target=True` to `from_stats`.

## Outliers needs 20 rows per population

`Outliers` fits a statistical threshold to each population: the rows of one metric at one level, or within one class
under `classwise()`. It now fits one only to a population with at least 20 rows that hold a value. A smaller level, or a
smaller `classwise()` class, yields no findings. Before, `AdaptiveThreshold` fitted from 3 rows. A
{class}`~dataeval.utils.thresholds.ConstantThreshold` needs no data, so it still judges every population.

Below 20 rows, the default threshold flags clean data often enough that most findings are noise. On clean, normally
distributed values it flags this share of rows:

| Rows in the population | Rows flagged |
| --- | --- |
| 5 | 3.4 % |
| 10 | 0.17 % |
| 20 | 0.05 % |

To see what was skipped, read {attr}`.OutliersOutput.populations`. It lists every population with its size, whether it
was judged, and why not:

```python
result = Outliers().evaluate(metadata)
result.populations.filter(~pl.col("judged"))
```

If a population you need is skipped, collect more rows for it, or judge it with a `ConstantThreshold`.

`classwise(...).with_threshold(...)` now keeps the per-class populations. Before, `with_threshold` re-detected against
whole levels, so the classes were lost.

Results of `classwise()` and `per_class=True` now carry a `population` column that names the class each row was judged
in, such as `class_label=cat`.

## `aggregate_by_class` counts a box under its own class

On a result computed with `per_target=True`, `aggregate_by_class` joined each flagged box to the labels of its whole
image, so a box was counted once under every class in the image. It now joins a box to its own label. On any result, a
flagged image row now counts once under each distinct class among its labels. Before, it counted once per label, so an
image with boxes `[car, car, bus]` counted twice under `car`; it now counts once.

Expect lower per-class totals for images that hold boxes of more than one class, and for images that hold more than one
box of a class.

## Outliers thresholds metadata factors

`Outliers.evaluate` accepts a {class}`.Metadata` as `data` and thresholds its ordered factors -- numeric or temporal by
their raw type -- each against the rows at the level it was measured at, so a track is compared with tracks and a frame
with frames. `factors=[...]` names which. Only raw values are read, so re-binning a metadata never changes the result.
Categorical factors, including integers with a declared vocabulary, are not thresholded.

`levels=` names the levels to judge, with the same names and rules as {meth}`.Duplicates.evaluate`: `"item"` and
`"target"` for image and detection data, and `"sequence"`, `"unit"`, `"track"` and `"instance"` for tracking data.
Passing `levels` together with `per_image` or `per_target` raises. Without either, a tracking metadata judges its
sequence and frame levels, as `Duplicates` does, so judge track factors with `levels="track"`. `per_target=True` adds
every detection and track.

{class}`.OutliersOutput` gains `.items`, `.targets`, `.sequences`, `.frames`, `.tracks` and `.detections`, which narrow
a result to one level and keep re-detecting at that level. On a result that holds frames or tracks,
`aggregate_by_metric` adds a `level` column and counts each flagged frame, track, detection or item once, and
`aggregate_by_class` raises, since a frame or a track has no class. Narrow to `.targets` first.

## Parity reports cells and statuses

{class}`.Parity` ⚠️ and {func}`.parity` ⚠️ are experimental, so these changes move inside the experimental contract.
Parity now tests each factor over independent images or sequences and reports every (factor, level, class) cell. See
[Parity](../concepts/Parity.md) for the method.

**`ParityOutput.insufficient_data` is removed.** It listed, per factor and level, the cells with small counts. A
combination that never occurs has no row in any table, so it never appeared there, and the mapping could not show what
the dataset lacks. The new {attr}`.ParityOutput.cells` frame has one row per factor, observed level and observed class,
observed zeros included, and marks the cells too thin to rely on:

```python
result.insufficient_data["illum_lux"]  # v1.1
result.cells.filter(pl.col("is_sparse") & (pl.col("factor_name") == "illum_lux"))  # v1.2
```

Each cell carries `observed`, `expected`, `deficit` (expected minus observed), `lift` (observed over expected), an exact
two-sided `p_value` and its `p_value_adjusted`, `is_deviant`, `is_sparse`, a `status` (`underrepresented`,
`overrepresented`, `too_thin`, `no_finding` or `untestable`) and `is_actionable`.

**The factors frame changes:**

| v1.1 | v1.2 |
| --- | --- |
| `is_significant` | `is_associated`, which reads the Benjamini–Hochberg adjusted p-value |
| `p_value` from the G-test (log-likelihood ratio) | `p_value` from Pearson's chi-squared test, or the Rao–Scott F when rows are grouped, plus `p_value_adjusted` |
| `has_insufficient_data`: an observed cell count below 5 | `has_insufficient_data`: Cochran's criterion on the expected counts, divided by the design effect, or fewer than 4 design degrees of freedom |
| a constant factor scores 0 with p = 1 | NaN results and `status="untestable"`, never a verdict of independence |
| | `status`: `associated`, `weak`, `inconclusive`, `not_detected` or `untestable` |
| | `design_effect`, `effective_groups`, `df_num` and `df_den` |

Every flag now reads the adjusted p-value, so a factor significant at a raw p of 0.04 among several factors can stop
being `associated`. Detections are grouped by image and frames by sequence, so p-values on object detection and
tracking datasets are larger than in v1.1, whose row-level p-values on such data were invalid.

**New configuration:** `lift_threshold=1.25`, at least 1, sets how far a significant cell's lift must be from 1 for the
cell to be actionable, and 1 disables the band. `assume_independent=False` is described in the next section.

**New output fields:** `test` (`"pearson"` or `"rao_scott_f"`), `group_source`, `group_level`, `n_rows` and `n_groups`.
`meta().state` adds `lift_threshold`, `assume_independent`, `group_source` and `test`.

**Core `parity`.** `ParityResult` removes `insufficient_data` and adds `chi_squared`, `df_num`, `df_den`,
`p_values_adjusted`, `design_effects`, `effective_groups`, `insufficient`, `testable`, `cells` (a `ParityCells` of flat
per-cell arrays), `test`, `n_rows` and `n_groups`. Its third argument is `groups`, one independent group id per row.
Pre-release builds of 1.2 had an `effective_n` argument in that position; `groups` replaces it.

## Parity needs an independent sampling unit

Parity must know which rows are independent of each other. It reads that from the input's structure: a
{class}`.Metadata` groups by its `item_indices` at any view, so detections group by image and frames by sequence
(`group_source="level"`), a container with many-to-one `item_indices` groups by them (`"item"`), and one row per item
needs no grouping (`"rows"`). A {class}`.Metadata` built from a dataset always records its structure, so these calls
are unchanged except for their numbers.

When nothing records the unit, Parity now raises `ValueError` instead of treating every row as independent. This
reaches only custom {class}`.MetadataLike` containers that carry no `item_indices`. Parity does not apply the protocol's
default of one label per item, because a container that silently lacks `item_indices` is the case the refusal guards
against. Give the container `item_indices` (label → item), or declare the rows independent:

```python
Parity().evaluate(custom_metadata)  # v1.1: rows read as independent; v1.2: ValueError
Parity(assume_independent=True).evaluate(custom_metadata)  # v1.2, when each row is its own item
```

Core {func}`.parity` takes the grouping directly, and needs `groups` or `assume_independent=True`:

```python
parity(factor_data, class_labels)  # v1.1: row-level test; v1.2: ValueError
parity(factor_data, class_labels, assume_independent=True)  # v1.2, the v1.1 row-level test
parity(factor_data, class_labels, item_ids)  # v1.2, rows grouped by item
```

Passing both `groups` and `assume_independent=True` raises as well. `group_source="declared"` records that the caller
made the declaration, and the p-values hold only if it is true.

## `label_parity` tests homogeneity

{func}`.label_parity` is stable, and this is a correctness fix. In v1.1 it ran a goodness-of-fit test that treated the
expected labels as the exact population. With both samples drawn from one distribution, that test rejected at
α = 0.05 in 27% of draws at 1,000 against 1,000 labels, 87% at 200 against 2,000, and 30% at 100 against 100. A
homogeneity test on the same draws rejected 4.4–6.5%. It was also asymmetric: swapping the two arguments moved one
p-value from 1.7 × 10⁻⁷ to 0.39. And it broke at the edges: `num_classes` above the classes present gave NaN, a class
absent from the expected labels gave an infinite statistic and p = 0, and samples with different largest labels raised
unless `num_classes` was passed.

v1.2 runs Pearson's chi-squared test of homogeneity on the 2 × K table of class counts, identical to
`scipy.stats.chi2_contingency(table, correction=False)`. It is symmetric in its two arguments and returns no NaN or
infinity for those inputs. **Every statistic and p-value changes.** The result adds `score` (bias-corrected Cramér's V
between dataset and class), `insufficient`, `df_num`, `df_den` and `test`.

**Detections need groups.** Read as independent labels, two detection datasets with the same class distribution but
different image counts and detections per image were declared different 84–91% of the time at α = 0.05 in simulation;
grouped by image, 4.4–4.7%. New keyword arguments `expected_groups` and `observed_groups` take one group id per label,
the item index for detections or the sequence id for tracks. Pass both or neither.

**Two deprecations**, both warning with `DeprecatedWarning`, a `FutureWarning`:

- Calling without groups and without `assume_independent=True` still runs as if every label were independent, but
  warns. From 2.0 it raises. `assume_independent=False` without groups raises now.
- `num_classes` is ignored, since the classes are the ones that occur in either sample. Passing it warns, and it is
  removed in 2.0.

```python
label_parity(expected, observed, num_classes=10)  # v1.1
label_parity(expected, observed, assume_independent=True)  # v1.2, one label per image
label_parity(expected, observed, expected_groups=expected_items, observed_groups=observed_items)  # v1.2, detections
```

See [Label parity](../concepts/DistributionShift.md#label-parity) for the population, the vocabulary requirement and
how to read a result.

## Overwriting a factor keeps the old column

{meth}`.Metadata.add_factors` with `overwrite=True` no longer discards the column it replaces. The incoming values take
the name. When the write would replace values, by changing a row's value, making it missing, or moving the factor to
another level, the column as it was moves to `<name>_original`, or `<name>_original_2` and so on when that is taken.
A write that only fills empty rows, or writes back the values already there, moves nothing aside, so re-running an
overwrite adds no columns. A keyed overwrite still replaces only the rows its keys name, and keeps the whole prior
column when it replaces a value.

The moved column is kept but not analyzed. `rows_at` and `dataframe` read its values, and `factor_info` describes it,
but it is left out of `factor_names`, `factor_data` and every evaluator, whatever `exclude` holds. To analyze it, name
it in `include`, for example `md.include = ["brightness", "brightness_original"]`. Because `factor_info` describes it,
the keys of `factor_info` can include a name `factor_names` does not, so pair the two by name rather than by position. A
column stored under `<name>_added` by `overwrite=False` is analyzed as before.

One moved column is not kept for good. A roll-up output keeps its roll-up's record, so when a source of that roll-up
later changes, the stale moved column is dropped and the roll-up is recomputed under the name it asks for, renamed if
the overwrite took that name.

{class}`.FactorInfo` gains `source_name`, the name a factor had in its source before DataEval renamed the column. A
dataset key `level`, stored as `metadata_level`, records `level`, and both `brightness_added` and `brightness_original`
record `brightness`. Saved metadata keeps these names, and a file saved by an earlier version reads each column as its
own source name.

## Partial keyed `source_index`

{meth}`.Metadata.add_factors` accepts addresses that carry a key and name only some rows of their level. Previously, a
source index had to name every row at each level it addressed, and naming fewer raised `ShapeMismatchError`. A key names
one row, so findings measured on some of a video's frames now attach to the full dataset:

```python
md.add_factors({"blur": [0.2, 1.0]}, source_index=[SourceIndex(0, 2, "unit"), SourceIndex(1, 0, "unit")])
```

Rows no address names are null. A keyed `source_index` write folds into a factor of the same name exactly as a `key=`
write does: a later write that names only rows still null fills them in rather than being stored as `<name>_added`, and
naming a row that already holds a value is a collision, which `overwrite` decides. Addresses without a key, such as
`SourceIndex(3)`, still have to name every row at their level.

## `ber_knn` lower bounds move

`ber_knn` could report a lower bound above the true Bayes error. Its plurality vote broke ties toward the smallest
label, which made an even `k` err far more than the constants it divided by assume: with a constant posterior of
0.9 (Bayes error 0.1), `k=2` reported a lower bound of 0.125. Three changes keep the bound below the Bayes error:

- Ties go to the tied label whose member is nearest, so an even `k` votes like `k - 1` and takes its constant.
- Devroye's constant applies only for odd `k >= 5`, where he states it; elsewhere the tighter FeeBee constant
  applies.
- With more than two classes, the bound comes from the 1-NN error, for any `k`, since Cover & Hart's inequality is
  about the 1-NN error.

The lower bound is also clamped to the upper bound, which is an error the k-NN classifier achieves. `upper_bound`
changes only where ties occur. `ber_knn` also accepts Python lists for `class_labels`, as documented, and a new
`groups=` argument.

## Feasibility judges targets with evidence

{class}`.Feasibility` is a new experimental evaluator in `dataeval.performance`. For each target, a metric and a
threshold, it returns one of five determinations (`evidence_conflict`, `demonstrated_feasible`,
`infeasible_under_recorded_assumptions`, `not_ruled_out`, `unresolved`) and the evidence behind it: ceilings, upper
endpoints on what any model in a stated class can reach, and witnesses, lower endpoints on what a frozen model
reaches. Every endpoint is a finite-sample bound, and all the endpoints of one call hold together with probability at
least `1 - alpha`.

```python
from dataeval.performance import Feasibility

result = Feasibility().evaluate(dataset, target={"accuracy": 0.95}, embeddings=embeddings)
result.determinations  # one row per target
result.evidence  # the evidence items each row cites
```

This release covers image and video classification, with accuracy and AP targets and, for image classification, a
per-class recall target at a stated false-positive limit:

```python
from dataeval.performance import TargetSpec

tank = TargetSpec(task="IC", metric="recall", threshold=0.9, class_name="Tank", max_false_positive_rate=0.05)
result = Feasibility().evaluate(dataset, target=[tank], embeddings=embeddings, predictions=decisions)
```

A recall target counts a witness only when its own false-positive upper endpoint is within the limit, and its ceiling
bounds the recall any model in its scope reaches at that limit. It is refused on grouped data, with
`false_positive_scope="each_class"` and as a mapping key. `predictions=` also accepts a 1-D integer array of class
decisions, whose rule you record in `provenance["decision_policy"]`, and when the requirement is stated on a vocabulary
coarsened by {class}`.Relabel`, `Relabel.fold_scores` folds the model's class scores through the same map. Bounds on
Bernoulli trials use exact Clopper–Pearson endpoints on ungrouped data, `FeasibilityOutput.aggregate_by_evidence()` has
a `quantity` column, and `print(result)` lays out one row per requirement followed by next steps and notes.

Object detection and tracking datasets raise `NotImplementedError`. `Feasibility` does not use `ber_knn` or `ber_mst`,
whose bounds are asymptotic, so the `ber_knn` change above does not move its results. {class}`.TargetSpec`,
{class}`.SamplingPlan`, {class}`.Evidence` and {class}`.Endpoint` are exported from `dataeval.performance` alongside it,
and the bounds it composes are new experimental functions in `dataeval.core`: {func}`.mean_endpoint`,
{func}`.binomial_endpoint`, {func}`.ratio_endpoint`, {func}`.units_to_cross`, {func}`.zero_one_consensus`,
{func}`.cost_consensus`, {func}`.consensus_max`, {func}`.cost_consensus_max`, {func}`.kink_costs`,
{func}`.disjoint_panels`, {func}`.fit_partition`, {func}`.local_panel_bound`, {func}`.ap_upper_envelope`,
{func}`.ap_lower_staircase` and {func}`.witness_thresholds`.

See [Performance Limits](../concepts/PerformanceLimits.md#feasibility-determinations-with-evidence) and
[Feasibility Evidence](../concepts/FeasibilityEvidence.md).
