# Migrating from v1.1 to v1.2

v1.2 removes what v1.1 deprecated, and reshapes {class}`.SourceIndex` into an address that
names one row at one level.

v1.1 reorganized three areas that v1.0 code touches directly — how metadata is addressed, how
datasets are transformed, and what scale image statistics are read against. Each of those
changes left a deprecated spelling behind, with a warning pointing at its replacement and a
note that the old spelling would go away in the next minor release. **This release is that
removal.**

The fastest way to find what needs changing is to run your v1.1 pipeline with warnings
promoted to errors:

```bash
python -W error::DeprecationWarning your_script.py
```

That finds the one thing v1.2 newly deprecates — the retired `target` spelling, which still
works and warns. It does **not** find the removals below, which raise instead — check for
them by name.

## At a glance

| Area | You are affected if you | Status |
| --- | --- | --- |
| [Metadata levels](#metadata-levels) | read `Metadata.image_data`/`target_data`/`raw_data`, `get_image_factors`/`get_target_factors`/`has_targets`/`filter_by_factor_type`, set `target_factors_only`, or pass `level="combined"` | **removed** |
| [View and operations](#view-and-operations) | import from `dataeval.selection`, import a dataset operation from `dataeval.utils.data`, or reference `Select` | **removed** |
| [Per-channel rows](#the-per-channel-row-path-is-removed) | pass `per_channel=` (with **any** value) or `channels=True` to `compute_stats`, or read `SourceIndex.channel` | **removed** |
| [Preprocessing helpers](#preprocessing-helpers) | use `BitDepth`/`get_bitdepth`/`clip_and_pad` | **removed** |
| [`SourceIndex` is an address](#sourceindex-is-an-address) | read `SourceIndex.target`, or build or unpack a `SourceIndex` positionally | *renamed* |
| [Evaluators report at a level](#evaluators-report-at-the-level-they-detected-at) | read `Outliers`/`Duplicates` results from statistics that address a level | *additive* |
| [`MetadataLike`](#metadatalike) | implement the protocol with `is_discrete` | **removed** |
| [`discrete_features`](#discrete_features) | call `mutual_info` without `discrete_features=`, or pass it to `mutual_info_classwise` | required / **removed** |
| [Extractors](#extractors) | use `ClassifierUncertaintyExtractor` | **removed** |
| [The `score` column](#the-score-column-is-one-confidence-per-row) | read `score` off the metadata dataframe, or relabel a dataset whose targets score every class | *changed* |

If none of those apply, upgrading is a version bump.

---

## Metadata levels

v1.1 kept the old image/target members as thin shims that warned. The shims are gone, so the
v1.1 table is now the only mapping:

| Removed in v1.2 | Use |
| --- | --- |
| `md.image_data` | `md.rows_at(md.item_level)` |
| `md.target_data` | `md.rows_at(md.label_level)` |
| `md.raw_data` | `md.rows_at(md.view).select(md.factor_names).to_numpy()` |
| `md.target_factors_only` | `md.at(level)` to choose rows, `md.inherited` to choose whether ancestor factors count |
| `md.get_image_factors(i)` | `md.rows_at("unit").filter(pl.col("item_index") == i)` |
| `md.get_target_factors(i, t)` | `md.rows_at(md.label_level).filter((pl.col("item_index") == i) & (pl.col("target_index") == t))` |
| `md.has_targets()` | `md.multi_target` |
| `md.filter_by_factor_type(t)` | `md.filter_by_factor(lambda _, fi: fi.factor_type == t)` |

Two factor behaviors went with it. `level="combined"` — v1.1's name for an array ordered by
`(item, target)` — was never a level, and it is no longer accepted. And
{class}`.Metadata`'s `add_factors` no longer infers a level from a factor's length: every
`add_factors` call must pass `level=` or `source_index=`, and omitting both raises
`ValueError`.

---

## View and operations

The `dataeval.selection` module is gone, and `dataeval.utils.data` no longer forwards the
dataset operations that moved out of it in v1.1. {class}`.View` and its operations, under
{mod}`dataeval.data`, are the only spelling:

| Removed in v1.2 | Use |
| --- | --- |
| `dataeval.selection.Select` | {class}`.View` |
| `Select(ds, selections=...)` | `View(ds, operations=...)` |
| `.selection_groups` | `.operation_groups` |
| `Selection` / `Selector` subclass | subclass {class}`.Operation`, implement `apply(view)` |
| `dataeval.selection.*` | `dataeval.data.*` |
| `dataeval.utils.data.split_dataset` / `unzip_dataset` / `TrainValSplit` / `DatasetSplits` | `dataeval.data.*` |

`dataeval.utils.data` itself stays: {func}`.validate_dataset`, `DatasetKind` and
`requires_maite_dataset` were never deprecated and are still imported from there.

---

## The per-channel row path is removed

`compute_stats(per_channel=True)` returned one row per channel, addressed by a third field
on {class}`.SourceIndex`. That field is gone, and with it the argument, its `channels=True`
spelling, and the `channel_index` column {class}`.Outliers` produced from it.

The replacement shipped in v1.1: name the bands you want and get **columns**.

```python
compute_stats(images, per_channel=True)  # v1.1, deprecated
compute_stats(images, channels={"r": 0, "g": 1, "b": 2})  # v1.2
```

Band groups are ordinary factors, which is the point — a channel had no level to land on,
so per-channel rows could never reach {class}`.Metadata`, and balance, diversity and parity
could not see them. `nir_mean` is a column and they can.

**`per_channel=False` has to go too.** The argument is gone, not just its `True` value, so
passing it either way is now a `TypeError`. This is the one change here that v1.1 gave no
warning for — v1.1 warned only when `per_channel` was truthy — so delete the argument
wherever it appears, including where it was spelled out as the default:

```python
compute_stats(images, stats=ImageStats.PIXEL, per_channel=False)  # v1.1
compute_stats(images, stats=ImageStats.PIXEL)  # v1.2
```

**{class}`.Outliers` no longer emits `channel_index`.** The column was populated only by the
row path. Band groups are thresholded independently per column, which is a better answer
than the pooled one the rows gave — a single threshold used to span every band of every
image.

**{func}`.compute_ratios` matches on the item alone.** It paired a box row with the image
row sharing its `(item, channel)`; there is no channel to share. The check that the two
inputs were computed with matching `per_channel` settings is gone with the argument.

## Preprocessing helpers

The v1.1 renames in {mod}`.utils.preprocessing` are through their deprecation window, so the
old names are gone:

| Removed in v1.2 | Use |
| --- | --- |
| `BitDepth` | {class}`.ValueRange` |
| `get_bitdepth()` | {func}`.get_value_range` |
| `clip_and_pad(img, box)` | {func}`.crop_with_fill` with `fill=np.nan`, take the first tuple value |

`clip_and_pad` is the one the v1.1 rename table did not list; it carried the same deprecation
and is now gone.

## `SourceIndex` is an address

The third field did not disappear so much as change job. {class}`.SourceIndex` still has
three fields, and the third is now `level` — which level the second one addresses — so that
one tuple can name a row anywhere in a dataset's level graph rather than only an item and
its boxes.

```python
SourceIndex(item, target, channel)  # v1.1
SourceIndex(item, key, level)  # v1.2
```

**`target` is renamed to `key`.** Each level names its rows with a different column, and
`key` holds that column's value — `target_index` for an instance, `unit_index` for a video
frame, `track_id` for a track. `target` still reads and still constructs, with a
`DeprecationWarning`, and is removed in v1.3.0:

```python
si.target  # v1.2: works, warns
si.key  # v1.2

SourceIndex(item=3, target=7)  # v1.2: works, warns
SourceIndex(item=3, key=7)  # v1.2
```

**Positional construction and unpacking still take three values, with a different third.**
Unpacking is silent — `item, target, channel = source_index[0]` still binds three names, and
the third is now a level. Construction is not: a v1.1 `SourceIndex(0, 1, 2)` raises, because
`2` is not one of the four level names.

```python
item, target, channel = source_index[0]  # v1.1
item, key, level = source_index[0]  # v1.2

SourceIndex(0, 1, 2)  # v1.2: ValueError, "level=2 is not a level"
```

*Which* levels exist depends on the dataset, so an address naming a level your data does not
have is caught where the address is used rather than where it is built.

**The string form keeps three parts.** `str(si)` produces `"3"`, `"3/7"` or `"3/12/unit"`,
and `SourceIndex.from_string` accepts those shapes plus `"3/-/sequence"` for a level stated
without a key. A third part that is not one of `sequence`, `unit`, `track` or `instance` is
rejected — where v1.1 read it as a channel number.

**Producers leave the level unstated, and so should you.** An unstated level is the
task-generic reading — the item level with no key, the label level under one — which is what
`SourceIndex(3)` and `SourceIndex(3, 7)` have always meant and still mean. State a level only
where an unstated one would resolve to a different one, which is `unit` and `track`.

That is a convention rather than a rule, and it matters because two spellings of one address
are not `==` and do not hash alike: `SourceIndex(3, 7)` and `SourceIndex(3, 7, "instance")`
are different keys in the mappings {class}`.Outliers` and {class}`.Duplicates` return.
{func}`.compute_stats` emits the minimal spelling.

### What this gains you

{meth}`.Metadata.add_factors` accepts an address at **any level the metadata has**, so a
per-frame or per-track measurement can be attached one value at a time rather than only as
whole keyed columns:

```python
md.add_factors({"speed": [...]}, source_index=[SourceIndex(0, 5, "track"), ...])
```

That is the same contract `add_factors(level=..., key=...)` has always offered a column at a
time — the address is `(item_index, key)` plus the level name. See
[](../concepts/MetadataLevels.md#naming-a-row-keys-or-addresses).

One limit worth knowing: an address names a row without saying what it sits inside, so
{meth}`.Metadata.from_factors` given addresses still builds the two-level shape only.
Nothing in a source index says which frame a detection was seen in. Construct from the
dataset, then place.

### What does not change

`channels=` mappings, `value_range`, `normalize_pixel_values`, `per_image`, `per_target`
and `per_background` are untouched, and so is every statistic's value. A v1.1 call that did
not pass `per_channel` at all returns exactly what it returned.

## Evaluators report at the level they detected at

{class}`.Outliers` and {class}`.Duplicates` now read the level off each address rather than
inferring one from a missing field, and hand back the addresses that went in.

**Nothing changes for an image dataset.** {func}`.compute_stats` on images states no level,
so no new column appears and every result is what it was. What follows applies only to
statistics whose source index states one.

**Both gain a column.** `Outliers` results gain `level`, and `Duplicates` results gain
`address_levels`. They name the rows `target_index` cannot tell apart — a video frame and a
track are both keyed, and only the level separates them — so they are omitted entirely
wherever every finding is at one of the two ends, which is every image dataset. `Duplicates`
keeps its existing `level` column, whose vocabulary is still `"item"` and `"target"`: that
says which *role* a group was detected in, where `address_levels` says which metadata level
each member names.

**Findings are reported in an address's canonical spelling**, not echoed back verbatim.
`SourceIndex(3, 7, "instance")` comes back as `SourceIndex(3, 7)`, and `SourceIndex(3, None,
"sequence")` as item `3` — an item has exactly one own-row, and a key already says a row is
one of its item's labels. That is what makes two runs over differently-spelled statistics
produce equal results.

**Readings of one kind of row are kept apart from readings of another.** A threshold is a
distribution fitted to the values under it, so `Outliers` fits one per level — a per-frame
reading is never compared against a spread that includes per-sequence ones. `Duplicates`
buckets before it hashes, for the same reason: a video frame is not a duplicate of a
detection inside it.

**`per_image` and `per_target` gate the two ends, whichever spelling names them.** The flags
name an item's own row and one of its labels, and an address says which of those it is
regardless of how it was spelled — so `SourceIndex(3, 7)` and `SourceIndex(3, 7, "instance")`
are gated identically, as are `SourceIndex(3)` and `SourceIndex(3, None, "sequence")`. A
statistic addressed at a level *between* the two, such as a video frame or a track, is
neither, so neither flag has a say over it and it is always included; the accessors then use
{class}`.SourceIndex` keys whatever the flags say, since no plain item index can name such a
row.

Findings then feed straight back in, because an evaluator's keys and
{meth}`.Metadata.add_factors` speak the same vocabulary:

```python
outliers = Outliers().from_stats(frame_stats)
md.add_factors(
    {"is_outlier": [address in outliers.outliers for address in addresses]},
    source_index=addresses,
)
```

## `MetadataLike`

The `is_discrete` fallback {class}`.MetadataLike` used to accept is gone. v1.1 still accepted
an `is_discrete` member and warned once per class; in v1.2 the fourth protocol member is
`is_binned` and there is no fallback, so a container that defines only `is_discrete` no longer
satisfies the protocol.

{class}`.MetadataLike` itself stays — it is now an alias for {class}`.CodedMetadataLike` — and
{class}`.Metadata` is unchanged. This only affects you if you implement the protocol by hand.

---

## `discrete_features`

Both core mutual-information functions keep `discrete_features`; in v1.2 it simply became
load-bearing in one direction and gone in the other.

- {func}`.mutual_info` — `discrete_features` is now **required**. Omitting it raises
  `TypeError` (v1.1 auto-detected and warned). Pass
  `discrete_features=[not b for b in md.is_binned]`.
- {func}`.mutual_info_classwise` — the `discrete_features` argument is **removed**; passing it
  raises `TypeError`. It never had any effect — the declaration was discarded downstream.

{class}`.Balance` is unaffected: it always passed the value explicitly.

---

## Extractors

`ClassifierUncertaintyExtractor` is gone. Wrap a `TorchExtractor` — or any
{class}`.FeatureExtractor` — in {class}`.UncertaintyExtractor` for per-instance uncertainty, or
in {class}`.ClasswiseUncertaintyExtractor` for per-class.

## The `score` column is one confidence per row

MAITE lets a target score either every box (`(N,)`) or every class of every box
(`(N, CLASSES)`), and a classification target *is* a score vector. v1.1 put whichever
arrived straight into the dataframe, so `score` was `Array(Float32, n_classes)` for those
datasets and `Float32` for the rest. Its width was therefore a property of the dataset's
class count, which is why two datasets with different vocabularies could not be stacked
into one frame at all — {func}`.merge_datasets` over them raised from `np.concatenate`.

`score` is now always `Float32`: **the row's confidence in its own class**, read down from
whichever layout the target carried, and **null** where there is none to read. If you were
recovering per-class probabilities with `md.dataframe["score"].to_numpy()`, read them from
the target instead — {class}`.SourceLocator` retrieves a detection, and
{class}`.ScoresExtractor` returns the full per-class rows for a model's predictions.

{class}`.Relabel` conforms scores as well as labels for the same reason. A per-class array
is indexed by the vocabulary it was measured against, so v1.1's relabeled detections kept
source-indexed columns beside target-indexed labels — a detection's score was read from
another class's column, or from off the end of the array. Detection scores are now reduced
to one confidence against the source label before the vocabulary changes; classification
vectors are folded into the target vocabulary, summing on a coarsening. A `Mapping[int, str]`
target vocabulary must index its classes non-negatively; a non-contiguous one is fine, and
no longer raises `IndexError`.

## Checklist

1. Replace the deprecated `Metadata` members using the table above.
2. Add `level=` or `source_index=` to every `add_factors` call; split any `level="combined"`
   array into one factor per level.
3. Move `dataeval.selection` imports, and any dataset operation still imported from
   `dataeval.utils.data`, to `dataeval.data`, and `Select` to `View`.
4. Delete `per_channel=` wherever it appears — `False` included — and replace a `True` with a
   `channels={...}` mapping.
5. Replace `BitDepth`/`get_bitdepth()`/`clip_and_pad()`.
6. Rename `SourceIndex.target` reads and `target=` construction to `key`, and check every
   positional `SourceIndex(a, b, c)` and three-name unpacking: the third value is a level now.
7. Implement `is_binned` on any hand-written `MetadataLike`.
8. Pass `discrete_features=` to `mutual_info`; drop it from `mutual_info_classwise`.
9. Replace `ClassifierUncertaintyExtractor`.
10. Read `score` as one confidence per row, and test an absent one with `is_null()` rather
    than by shape.
