# Migrating from v1.1 to v1.2

v1.2 removes features deprecated in v1.1. It also updates {class}`.SourceIndex` into an address that names one row at
one level.

v1.1 reorganized metadata addressing, dataset transformations, and image statistics scaling. Each change retained a
deprecated interface that emitted a warning pointing to its replacement. v1.2 removes those deprecated interfaces.

To identify code that requires updates, run your v1.1 pipeline with warnings promoted to errors:

```bash
python -W error::DeprecationWarning your_script.py
```

This flags `SourceIndex.target`, which is newly deprecated in v1.2 and emits a warning. It does not flag the removals
listed below, because those raise exceptions directly. Check for those removals by name.

| [View and operations](#view-and-operations) | import from `dataeval.selection`, import a dataset operation from `dataeval.utils.data`, or reference `Select` | **removed** |

## Metadata levels

v1.1 deprecated legacy image and target attributes with warnings. Those attributes are now removed. Use the following
replacements:

| Removed in v1.2 | Use |
| --- | --- |
| `md.image_data` | `md.rows_at(md.item_level)` |
| `md.target_data` | `md.rows_at(md.label_level)` |
| `md.raw_data` | `md.rows_at(md.view).select(md.factor_names).to_numpy()` |
| `md.target_factors_only` | `md.at(level)` to choose rows, `md.inherited` to choose whether ancestor factors count |
| `md.get_image_factors(i)` | `md.rows_at("unit").filter(pl.col("item_index") == i)` |
| `md.get_target_factors(i, t)` | `md.rows_at(md.label_level).filter((pl.col("item_index") == i) & (pl.col("target_index") == t))` |
| `md.has_targets()` | `md.multi_target` |
| `md.filter_by_factor_type(t)` | `md.filter_by_factor(lambda _, fi: fi.factor_type == t)` |

Two factor behaviors are also removed. The argument `level="combined"` was the v1.1 name for an array ordered by `(item,
target)`. It is no longer accepted. In addition, {meth}`.Metadata.add_factors` no longer infers a level from factor
length. Every `add_factors` call must pass `level=` or `source_index=`. Omitting both raises `ValueError`.

## View and operations

The `dataeval.selection` module is removed. The `dataeval.utils.data` module no longer forwards dataset operations. Use
{class}`.View` and its operations in {mod}`dataeval.data`:

| Removed in v1.2 | Use |
| --- | --- |
| `dataeval.selection.Select` | {class}`.View` |
| `Select(ds, selections=...)` | `View(ds, operations=...)` |
| `.selection_groups` | `.operation_groups` |
| `Selection` / `Selector` subclass | subclass {class}`.Operation`, implement `apply(view)` |
| `dataeval.selection.*` | `dataeval.data.*` |
| `dataeval.utils.data.split_dataset` / `unzip_dataset` / `TrainValSplit` / `DatasetSplits` | `dataeval.data.*` |

The `dataeval.utils.data` module remains available for utility functions. {func}`.validate_dataset`, `DatasetKind`, and
`requires_maite_dataset` were never deprecated and are still imported from that module.

## The per-channel row path is removed

In v1.1, `compute_stats(per_channel=True)` returned one row per channel, addressed by a third field on
{class}`.SourceIndex`. That field is removed. The `per_channel` argument, the `channels=True` alias, and the
`channel_index` column in {class}`.Outliers` are also removed.

To extract channel statistics, specify band names to produce columns:

```python
compute_stats(images, per_channel=True)  # v1.1, deprecated
compute_stats(images, channels={"r": 0, "g": 1, "b": 2})  # v1.2
```

Band groups produce factor columns rather than separate rows. Channels do not correspond to a metadata level, so
per-channel rows could not be stored in {class}`.Metadata`. Consequently, evaluators such as balance, diversity, and
parity could not process them. Factor columns such as `nir_mean` are stored in metadata and evaluated directly.

**`per_channel=False` is also removed.** Because the parameter itself is removed, passing any value raises `TypeError`.
v1.1 warned only when `per_channel` was truthy. Remove `per_channel` wherever it appears, including calls that passed
the default `False`:

```python
compute_stats(images, stats=ImageStats.PIXEL, per_channel=False)  # v1.1
compute_stats(images, stats=ImageStats.PIXEL)  # v1.2
```

**{class}`.Outliers` no longer emits `channel_index`.** That column was populated only by per-channel rows. Band groups
are thresholded independently per column. Previously, per-channel rows used a single pooled threshold across every band
of every image.

**{func}`.compute_ratios` matches on item index alone.** Previously, it paired each bounding box row with the image row
sharing `(item, channel)`. Channel indices are removed, so rows are matched by item index. The validation check
requiring matching `per_channel` settings between inputs is also removed.

The deprecated names in {mod}`.utils.preprocessing` are removed:

| --- | --- |

| `get_bitdepth()` | {func}`.get_value_range` |
| `clip_and_pad(img, box)` | {func}`.crop_with_fill` with `fill=np.nan`, take the first tuple value |

`clip_and_pad` was deprecated in v1.1 and is now removed.

## `SourceIndex` is an address

{class}`.SourceIndex` retains three fields. The third field is now `level`, which specifies the metadata level addressed
by the second field (`key`). A single tuple can now name a row at any level in a dataset's level graph, rather than only
an item and its bounding boxes.

```python
SourceIndex(item, target, channel)  # v1.1
SourceIndex(item, key, level)  # v1.2
```

**`target` is renamed to `key`.** Each level identifies rows by a specific column. `key` holds that column's value, such
as `target_index` for an instance, `unit_index` for a video frame, or `track_id` for a track. Accessing `target` or
passing `target=` to the constructor still works but emits a `DeprecationWarning`. The `target` attribute and parameter
will be removed in v1.3.0.

```python
si.target  # v1.2: works, warns
si.key  # v1.2

SourceIndex(item=3, target=7)  # v1.2: works, warns
SourceIndex(item=3, key=7)  # v1.2
```

**Positional construction and unpacking still take three values, but the third value is now a level name.** Unpacking
`source_index[0]` binds `(item, key, level)`. Positional construction validates the level name. For example,
`SourceIndex(0, 1, 2)` raises `ValueError` ("level=2 is not a level") because `2` is not a valid level name.

```python
item, target, channel = source_index[0]  # v1.1
item, key, level = source_index[0]  # v1.2

SourceIndex(0, 1, 2)  # v1.2: ValueError, "level=2 is not a level"
```

Available levels depend on the dataset. An address naming a level absent from your data is caught when the address is
used, rather than when it is built.

**The string representation retains up to three parts.** `str(si)` produces `"3"`, `"3/7"`, or `"3/12/unit"`.
`SourceIndex.from_string` accepts those formats, as well as `"3/-/sequence"` for a level stated without a key. The third
part must be one of `sequence`, `unit`, `track`, or `instance`. Any other value is rejected. In v1.1, that segment was
read as a channel number.

**Leave the level unstated unless addressing `unit` or `track`.** An unstated level resolves to the item level when key
is omitted, or to the label level when key is provided. `SourceIndex(3)` addresses an item. `SourceIndex(3, 7)`
addresses a label. Specify a level explicitly only when addressing intermediate levels such as `unit` or `track`.

Address equality and hashing depend on exact representation. `SourceIndex(3, 7)` and `SourceIndex(3, 7, "instance")` are
not equal and have different hash values. They act as distinct keys in dictionary results returned by {class}`.Outliers`
and {class}`.Duplicates`. {func}`.compute_stats` emits the minimal form without an explicit level.

### Addressing arbitrary metadata levels

{meth}`.Metadata.add_factors` accepts addresses at any metadata level. Per-frame or per-track measurements can be
attached as individual values instead of entire keyed columns:

```python
md.add_factors({"speed": [...]}, source_index=[SourceIndex(0, 5, "track"), ...])
```

This matches the column-oriented contract of `add_factors(level=..., key=...)`. The address consists of `(item_index,
key)` and the level name. See [](../concepts/MetadataLevels.md#naming-a-row-keys-or-addresses).

An address identifies a row, but does not specify hierarchical containment. For example, a source index does not
indicate which frame contains a detection. Consequently, {meth}`.Metadata.from_factors` given addresses builds only the
two-level structure. To preserve full hierarchy, construct {class}`.Metadata` from the dataset first, then add factors.

### Unchanged functionality

The `channels=` mapping, `value_range`, `normalize_pixel_values`, `per_image`, `per_target`, and `per_background`
parameters remain unchanged. Computed statistic values are also unchanged. Calls that omitted `per_channel` in v1.1
return the same results in v1.2.

## Evaluators report at the level they detected at

{class}`.Outliers` and {class}`.Duplicates` read the level directly from each address rather than inferring it from
missing fields. Both evaluators return the input addresses in their results.

**Image dataset results are unchanged.** For image datasets, {func}`.compute_stats` emits addresses without an explicit
level. Output columns and values remain identical to v1.1. The changes below apply only when a statistic source index
specifies an explicit level.

**Both evaluators add a level column.** `Outliers` results add a `level` column, and `Duplicates` results add an
`address_levels` column. These columns distinguish rows that share key indices, such as video frames and tracks. When
all findings occur at either the item level or the label level, as in image datasets, these columns are omitted. In
`Duplicates`, the existing `level` column is retained with values `"item"` and `"target"`. That column indicates the
detection role of a group, while `address_levels` indicates the metadata level of each member.

**Findings normalize addresses to canonical form.** Evaluators return canonical addresses rather than echoing input
formats verbatim. For example, `SourceIndex(3, 7, "instance")` normalizes to `SourceIndex(3, 7)`. `SourceIndex(3, None,
"sequence")` normalizes to item index `3`. An item has one root row, and a key indicates a label row. Normalization
ensures that runs over equivalent addresses produce identical results.

**Evaluators partition statistics by metadata level.** `Outliers` fits a separate threshold distribution for each
metadata level. Per-frame statistics are evaluated only against other per-frame statistics, rather than across
per-sequence statistics. `Duplicates` partitions candidates by level before hashing. This prevents comparisons across
different metadata levels.

**`per_image` and `per_target` filter item and label levels regardless of address format.** Equivalent addresses are
filtered identically. `SourceIndex(3, 7)` and `SourceIndex(3, 7, "instance")` are filtered identically, as are
`SourceIndex(3)` and `SourceIndex(3, None, "sequence")`. Intermediate levels, such as video frames or tracks, are
unaffected by these flags and are always included. Result accessors for intermediate levels use {class}`.SourceIndex`
keys, because integer item indices cannot identify those rows.

Evaluator output addresses can be passed directly to {meth}`.Metadata.add_factors`:

```python
outliers = Outliers().from_stats(frame_stats)
md.add_factors(
    {"is_outlier": [address in outliers.outliers for address in addresses]},
    source_index=addresses,
)
```

## `MetadataLike`

The fallback for `is_discrete` in {class}`.MetadataLike` is removed. In v1.1, defining `is_discrete` emitted a warning.
In v1.2, the fourth protocol member is `is_binned`. Containers that define only `is_discrete` no longer satisfy the
protocol.

{class}`.MetadataLike` remains available as an alias for {class}`.CodedMetadataLike`. {class}`.Metadata` is unchanged.
This change affects only custom classes that implement the protocol directly.

---

## `discrete_features`

The `discrete_features` parameter was updated across mutual information functions.

- In {func}`.mutual_info`, `discrete_features` is now **required**. Omitting it raises `TypeError`. In v1.1, omitting it
  triggered auto-detection and emitted a warning. Pass `discrete_features=[not b for b in md.is_binned]`.
- In {func}`.mutual_info_classwise`, the `discrete_features` parameter is **removed**. Passing it raises `TypeError`.
  The parameter previously had no effect and was discarded downstream.

{class}`.Balance` is unaffected. It always passed the value explicitly.

---

## Extractors

`ClassifierUncertaintyExtractor` is removed. Wrap a `TorchExtractor` or any {class}`.FeatureExtractor` in
{class}`.UncertaintyExtractor` for per-instance uncertainty. For per-class uncertainty, wrap the extractor in
{class}`.ClasswiseUncertaintyExtractor`.

## The `score` column is one confidence per row

In MAITE, a target can provide scores per bounding box (`(N,)`) or per class for each box (`(N, CLASSES)`). A
classification target is a score vector. In v1.1, metadata stored target scores directly in the dataframe. The `score`
column was `Array(Float32, n_classes)` for multi-class targets and `Float32` for single-score targets. Because column
width depended on class count, datasets with different vocabularies could not be concatenated into a single dataframe.
In those cases, {func}`.merge_datasets` raised an error from `np.concatenate`.

The `score` column is now always `Float32`. It stores the confidence of a row for its assigned class, extracted from
whichever layout the target provides. Rows without scores contain **null**. To access per-class probabilities, read them
from the target rather than `md.dataframe["score"].to_numpy()`. {class}`.SourceLocator` retrieves individual detections.
{class}`.ScoresExtractor` extracts per-class prediction arrays from model outputs.

{class}`.Relabel` aligns score arrays when transforming labels. Per-class arrays are indexed by their original
vocabulary. In v1.1, relabeled detections retained source-indexed score columns alongside relabeled targets.
Consequently, scores mapped to incorrect classes or exceeded array bounds. Detection scores are now reduced to a single
confidence value for the source label before vocabulary transformation. Classification vectors are mapped into the
target vocabulary, summing probabilities when classes are merged. A `Mapping[int, str]` target vocabulary must use
non-negative integer indices. Non-contiguous class indices are supported and no longer raise `IndexError`.

If code accesses `dataset[i][1].scores` from a relabeled detection dataset and requires per-class arrays during
migration, pass `Relabel(..., reduce_detection_scores=False)`. This maps scores into the target vocabulary. In v1.1, the
array retained the source vocabulary indexing and width. Verify any code that indexes the resulting array. Classes
missing from the source array receive a score of `0.0` rather than being treated as absent. Merged classes combine their
scores by summation.

Setting `reduce_detection_scores=False` does not change the metadata `score` column width. The column retains one value
per row under both settings. However, it changes the numeric values in that column because metadata reads from the
transformed target. When classes are merged, the column reflects the summed class score. Where scores cannot be read,
the column contains `0.0` instead of `null`. The `reduce_detection_scores` parameter emits a warning and will be removed
in v1.3. Omitting the parameter uses the default reduction behavior.

## A class axis of your own

{meth}`.Metadata.classed_by` configures one or more factors as the class axis. Unmodified metadata instances continue to
report default class labels.

```python
by_weather = metadata.classed_by("weather")
Balance().evaluate(by_weather)  # conditions on weather
Coverage().evaluate(by_weather, embeddings=emb)  # per-weather coverage
split_dataset(by_weather, stratify=True)  # folds balanced over weather
```

This configuration introduces three behaviors:

**Original dataset labels become a factor.** The pivoted metadata gains a factor named `class` containing the original
labels. Results retain the relationship between the custom axis and the original dataset labels.

**All class-label consumers use the pivoted axis.** {attr}`.Metadata.class_labels` and {attr}`.Metadata.index2label`
update together. Evaluators without an explicit `label=` parameter evaluate against the pivoted axis.
{class}`.Representation` is an exception because it validates label names against an ontology. It raises an error when
passed pivoted metadata.

**Results record the active class axis.** Class-conditional outputs add a `class_axis` field holding a
{class}`.ClassAxis`. The `meta().state` mapping adds `class_axis`, `class_axis_source`, and `class_axis_level` entries:

```python
result = Balance().evaluate(by_weather)
result.class_axis.source  # "derived" (custom axis rather than dataset labels)
result.class_axis.rows_per_group_entity  # 3.0 if a per-image axis was read from detections
```

For standard evaluations, `class_axis_source` records `"ground_truth"`. In previous releases, this field recorded the
string `"NoneType"`. When setting `label=` on bias evaluators, `class_axis_source` is recorded identically.

The class axis configuration persists across `at`, `where`, `having`, and `agg` operations. Like `view`, `include`, and
`exclude`, it is omitted during serialization with {meth}`.Metadata.save`.

See [](../notebooks/h2_analyze_by_custom_class_axis.py) for a worked example covering composite axes and metadata level
selection.

## Duplicates checks annotation and metadata factors

{class}`.Duplicates` now evaluates annotations and optional metadata factors alongside pixel checks. Datasets without
targets or `duplicate_factors` produce the same pixel-only results as v1.1.

**Datasets with targets include annotation duplicate rows.** When a dataset yields `(image, target, metadata)` and
targets contain `boxes` or `labels`, `Duplicates.evaluate` inspects annotations by default. Two additional result
patterns can appear:

- Groups whose `methods` list contains `"annotation"`. These represent items sharing identical annotations regardless of
  pixel similarity.
- Existing pixel groups (`dup_type="exact"` or `"near"`) where `differs_on` contains `"annotation"`. These represent
  matching images with differing annotations.

These additions do not replace previous findings. They provide new rows or additional fields on existing rows.

**Results add two columns: `differs_on` and `annotation_divergence`.** `differs_on` (`list[str] | None`) uses a
three-state representation. A `null` value indicates the axis was not evaluated. An empty list `[]` indicates the axis
was evaluated and values agreed. A populated list names the attributes that disagreed. `annotation_divergence` (`float |
None`) records divergence scores. See [Reading `differs_on` and the divergence
columns](../concepts/ActingOnResults.md#duplicates-and-near-duplicates) for the complete three-state contract and pair
row `mean_iou` behavior.

**Metadata factor grouping requires explicit configuration.** Passing `metadata=` and `duplicate_factors=[...]` to
`evaluate()` groups items whose specified factor values match exactly. These groups are reported with
`dup_type="factors"`. Omitting `duplicate_factors` disables factor grouping. No factors are evaluated by default.

**Every named factor must agree.** `duplicate_factors` functions as a conjunction. Items are grouped only when all
named factors match; matching some and differing on one produces no group. Adding factors narrows matches. Items
with unstated factors (null or NaN) are excluded from grouping. `factor_cardinality` counts stated values only.

**`evaluate()` accepts a `Metadata` instance directly.** When evaluating metadata alone, no pixels or annotations
are decoded, so `duplicate_factors` is required. The run reports at `level="item"` only, and `deduplicate()` reads
its item count directly from the metadata instead of requiring `n_items=`.

```python
# Unchanged from v1.1: image datasets without targets produce identical results
Duplicates().evaluate(images)

# New in v1.2: object detection datasets include annotation duplicate rows
Duplicates().evaluate(od_dataset)

# New in v1.2: optional grouping by specified metadata factors
Duplicates().evaluate(od_dataset, metadata=Metadata(od_dataset), duplicate_factors=["capture_id"])

# New in v1.2: all specified factors must agree
Duplicates().evaluate(od_dataset, metadata=Metadata(od_dataset), duplicate_factors=["capture_id", "camera_id"])

# New in v1.2: evaluate metadata directly without decoding images
Duplicates().evaluate(Metadata(od_dataset), duplicate_factors=["capture_id"])
```

**Existing group types are preserved.** The evaluator continues to report `exact`, `near`, and video group types
(`segment`, `aligned`, and `redundant`) as in previous releases.

## Checklist

1. Replace deprecated `Metadata` members using the table above.
2. Add `level=` or `source_index=` to every `add_factors` call. Split any `level="combined"` array into separate factors
   per level.
3. Update imports from `dataeval.selection` and `dataeval.utils.data` to `dataeval.data`. Replace `Select` with `View`.
4. Remove `per_channel=` arguments, including `per_channel=False`. Replace `per_channel=True` with a `channels={...}`
   dictionary.
5. Replace `BitDepth`, `get_bitdepth()`, and `clip_and_pad()` with their v1.2 equivalents.
6. Rename `SourceIndex.target` attribute access and `target=` construction arguments to `key`. Update positional
   construction and unpacking of `SourceIndex` so the third value represents `level`.
7. Implement `is_binned` on custom implementations of `MetadataLike`.
8. Pass `discrete_features=` to `mutual_info`. Remove `discrete_features=` from calls to `mutual_info_classwise`.
9. Replace `ClassifierUncertaintyExtractor` with `UncertaintyExtractor` or `ClasswiseUncertaintyExtractor`.
10. Update code reading `score` to expect a single float per row. Check for missing scores using `is_null()` instead of
    array shape. Note that `Relabel(..., reduce_detection_scores=False)` affects target layout rather than column width,
    and alters the values extracted into metadata.
