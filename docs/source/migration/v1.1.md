# Migrating from v1.0 to v1.1

DataEval v1.1 reorganizes three areas that v1.0 code touches directly — how metadata is
addressed, how datasets are transformed, and what scale image statistics are read against
— and adds several capabilities that need no migration at all.

Nothing in this release removes anything. Every v1.0 spelling still works and still returns
what it returned, with one exception noted below. What changes is that several of them now
warn, and a set of numbers moved because the reference they are measured against moved.

**The removals land in v1.2.** Everything marked deprecated here disappears in the next
minor release, so this is the window to migrate.

## At a glance

| Area | You are affected if you | Severity |
| --- | --- | --- |
| [Metadata levels](#metadata-levels-replace-the-image-and-target-split) | read `Metadata.image_data`, `target_data`, `raw_data`, or call `add_factors` without `level=` | deprecated, removed v1.2 |
| [View and operations](#select-became-view) | import from `dataeval.selection` or `dataeval.utils.data`, or subclass `Selection` | deprecated, removed v1.2 |
| [Image statistics](#image-statistics-changed-scale) | call `compute_stats` on anything but `uint8` with `normalize_pixel_values=False` | **numbers moved** |
| [Bias results](#balance-is-corrected-for-chance) | use `Balance` | **numbers moved** |
| [Extractors](#extractor-changes) | use `ClassifierUncertaintyExtractor` | deprecated, removed v1.2 |
| [Duplicates](#one-actual-removal) | index `DuplicatesOutput["dataset_index"]` | **removed in v1.1** |

If none of those apply, upgrading is a version bump.

## Metadata levels replace the image and target split

v1.0 addressed metadata with two fixed buckets: image-level factors and target-level ones.
That vocabulary assumed one shape of dataset — still images with boxes — and could not
describe a video frame belonging to a sequence, or a detection belonging to a track.

v1.1 replaces the pair with a **level graph**. The levels are `sequence`, `unit`, `track`
and `instance`; for a still-image task `unit` is the image and `instance` is the target, so
the old two-bucket model is the vision-shaped special case of the new one.

Read [Metadata levels](../concepts/MetadataLevels.md) for the model itself. The mechanical
migration is:

| v1.0 | v1.1 |
| --- | --- |
| `md.image_data` | `md.rows_at(md.item_level)` |
| `md.target_data` | `md.rows_at(md.label_level)` |
| `md.raw_data` | `md.rows_at(md.view).select(md.factor_names).to_numpy()` |
| `md.target_factors_only` | `md.at(level)` to choose rows, `md.inherited` to choose whether ancestor factors count |
| `md.get_image_factors(i)` | `md.rows_at("unit").filter(pl.col("item_index") == i)` |
| `md.get_target_factors(i, t)` | `md.rows_at(md.label_level).filter((pl.col("item_index") == i) & (pl.col("target_index") == t))` |
| `md.has_targets()` | `md.multi_target` |
| `md.filter_by_factor_type(t)` | `md.filter_by_factor(lambda _, fi: fi.factor_type == t)` |

Two caveats worth reading twice.

On a **single-target** task `image_data` returned the *labelled* rows rather than the image
rows. `rows_at(md.item_level)` returns the image rows. If you relied on the old behavior for
single-target data, use `md.rows_at(md.label_level)`.

The two `get_*_factors` rows also change container. `get_image_factors(i)` and
`get_target_factors(i, t)` each returned **one row as a `dict`**; their `rows_at(...)`
replacements return a one-row `DataFrame` holding the same values. Add `.to_dicts()[0]` if
a caller downstream expects the mapping:

```python
md.rows_at("unit").filter(pl.col("item_index") == i).to_dicts()[0]
```

The other six rows above are exact — `image_data`, `target_data`, `raw_data`,
`has_targets()` and `filter_by_factor_type()` each return the same values as their
replacement, verified by comparison.

### Say which level a factor belongs to

v1.0 inferred a factor's level from the length of its array. That works until two levels
have the same count, at which point it silently guesses. v1.1 asks you to say:

```python
# v1.0 — level inferred from array length
md.add_factors({"weather": weather_per_image})

# v1.1 — state the destination
md.add_factors({"weather": weather_per_image}, level="unit")

# or label each value, which compute_stats already does for you
md.add_factors(stats["stats"], source_index=stats["source_index"])
```

Inference still works and still warns. It is removed in v1.2.

`level="combined"` is also deprecated. It was never a level — it described an array ordered
the way `compute_stats` emits one. Pass `source_index=` instead, which labels each value
with what it describes rather than relying on ordering.

### Binning happens at a factor's own level

Continuous factors are discretized before any bias or diversity evaluator sees them. In
v1.1 that binning happens **at the level the factor lives at**, so a per-image factor is
binned over the image population and a per-detection factor over the detection population.
Results for a factor whose two populations have different distributions will differ from
v1.0 accordingly.

Two related corrections landed with it:

- Level splits that hold no values at their level are **dropped and reported** rather than
  carried as empty columns.
- Infinities are excluded when placing bin edges, alongside NaN. An infinity at the low end
  previously made the near-neighbor statistic NaN, at which point the threshold comparison
  failed open; one at the high end drove its windows to zero.

See [Binning](../concepts/Binning.md) for what binning does to results and how to control
it.

## Select became View

v1.0's `Select` could choose a subset of a dataset but not rewrite one. v1.1 replaces it
with {class}`.View`, built from an ordered pipeline of {class}`.Operation` that both selects
and transforms.

```python
# v1.0
from dataeval.selection import Select, ClassFilter, Limit

ds = Select(dataset, selections=[ClassFilter([0, 1]), Limit(100)])

# v1.1
from dataeval.data import View, ClassFilter, Limit

ds = View(dataset, operations=[ClassFilter([0, 1]), Limit(100)])
```

| v1.0 | v1.1 |
| --- | --- |
| `dataeval.selection.Select` | `dataeval.data.View` |
| `Select(ds, selections=...)` | `View(ds, operations=...)` |
| `.selection_groups` | `.operation_groups` |
| `Selection` / `Selector` subclass | subclass `dataeval.data.Operation`, implement `apply(view)` |
| `dataeval.selection.*` | `dataeval.data.*` |
| `dataeval.utils.data.*` | `dataeval.data.*` |

Both modules re-export their old names with a `DeprecationWarning` and drop them in v1.2.

`View` also accepts a plain image-only dataset. A target-bearing dataset is only required
when an operation actually reads targets — `ClassFilter`, `ClassBalance` and `Relabel`
declare that, while `Limit`, `Shuffle`, `Reverse` and `Indices` do not.

### New operations

v1.1 adds transform operations that v1.0 had no equivalent for: {class}`.Crop`,
{class}`.Resize`, {class}`.SelectChannels`, {class}`.DetectionCrops`,
{class}`.TorchvisionTransform` as an escape hatch, and {class}`.Relabel` for aligning class
labels against an ontology.

## Image statistics changed scale

Three changes to {func}`.compute_stats`, all of them about which reference a measurement is
taken against rather than about the measurement itself.

The comparisons below come from running 192 calls — eleven encodings, four statistic
families, and the `normalize_pixel_values` and `per_channel` switches — under v1.0.6 and
v1.1.0 and diffing the results. **137 were byte-identical, and nothing that worked before
stopped working.**

### `normalize_pixel_values` now defaults to False

Pixel statistics are reported in the units the data is stored in. A 12-bit image whose mean
read `0.4944` now reads `2024.59`.

Both behaviors were available in v1.0 and both still are — only the default flipped. Pass
the argument explicitly to pin it and silence the warning. Keep `True` when comparing images
stored at *different* bit depths; {class}`.Outliers` sets it internally for that reason.

This argument now scopes to `PIXEL` statistics only.

### Visual statistics read the 0–255 display range

`VISUAL_BRIGHTNESS`, `VISUAL_CONTRAST`, `VISUAL_DARKNESS`, `VISUAL_SHARPNESS` and
`VISUAL_PERCENTILES` are a perceptual reading. v1.0 took them against the scale the data was
stored on, so the answer came back in the units of the container. v1.1 resolves the display
range first, so one picture answers the same way in any encoding.

One picture in four lossless encodings:

| encoding | v1.0 brightness | v1.1 brightness | v1.0 sharpness | v1.1 sharpness |
| --- | --- | --- | --- | --- |
| `uint8` | 68.00 | 68.00 | 113.32 | 113.32 |
| `uint16` | 17476.00 | 68.00 | 127.28 | 113.32 |
| float `[0, 1]` | 0.2667 | 68.00 | 1.00 | 113.32 |
| float `0-255` | 68.00 | 68.00 | 113.32 | 113.32 |

`uint8` and float-boxed 8-bit take an identity path and are untouched. Stored v1.0 visual
statistics are on a different scale from fresh ones, so recompute before comparing.

If you passed a {class}`.ConstantThreshold` against a visual statistic its bounds need
rescaling. Every other threshold — `zscore`, `modzscore`, `iqr`, `adaptive` — is
location-scale equivariant, so **no outlier flag moves**.

### Float data no longer gets an inferred range

Some statistics need the interval the values occupy. Integer encodings state it; float data
does not. v1.0 inferred one from the observed extremes. v1.1 asks you to state it and
answers `NaN` where it has not been told, naming `value_range` in a warning.

```python
elevation = ...  # float, metres above and below sea level

compute_stats([elevation], stats=ImageStats.PIXEL_ENTROPY)  # NaN
compute_stats([elevation], stats=ImageStats.PIXEL_ENTROPY, value_range=(-50, 50))  # 5.3481
```

That warning goes to the `dataeval` logger rather than to Python's `warnings`, because it
is raised per datum and grouped by message with the affected indices. Call
{func}`dataeval.log` to see it — otherwise an all-`NaN` column is the only signal:

```python
import dataeval

dataeval.log()  # WARNING: ... pass value_range=(low, high) ... — indices: 0
```

Worth knowing what the v1.0 figure covered: signed values gave no depth to report, so the
histogram binned over `[0, 1]` and 762 of 768 pixels fell outside the bins — the entropy
described the six inside. Wide float data was read against a 16-bit range, placing values
spanning `0..40000` in its bottom 61%.

Statistics that go `NaN` without a readable range: the whole `VISUAL` family,
`PIXEL_HISTOGRAM`, `PIXEL_ENTROPY`, `DIMENSION_DEPTH`, and — only under
`normalize_pixel_values=True` — the rest of `PIXEL`. `PIXEL_MISSING` always answers,
because it measures the presence of data rather than the data.

The `[0, 1]` and `0-255` float conventions are still detected automatically.

### `per_channel=True` is deprecated

It still returns exactly what it did, now with a warning, and is removed in v1.2. It is
going because per-channel rows could never reach {class}`.Metadata`: a source index
addresses an item and a target, and a channel is a third axis with no level to land on, so
balance, diversity and parity could not see them.

```python
compute_stats(images, per_channel=True)  # v1.0
compute_stats(images, channels={"r": 0, "g": 1, "b": 2})  # v1.1
```

Band groups become ordinary columns. Three things to know:

1. **You gain measurements.** `depth` and the hashes were image-level only under the row
   path; band groups measure them per group, which is what lets {class}`.Duplicates`
   distinguish multispectral images by band.
2. **Geometry gets no band columns.** A band subset does not move a bounding box, so
   `width`, `height` and `center` stay unprefixed — they were `NaN` on channel rows anyway.
3. **There is no all-bands-separately column form.** You name the groups you want.

{class}`.Outliers` thresholding changes shape as a result, so expect different flags:
channel rows all had `target is None`, so one threshold was pooled across every band of
every image, where band columns are thresholded independently.

See [](../notebooks/h2_measure_channel_groups.py) for the full guide.

### Renamed helpers

| v1.0 | v1.1 |
| --- | --- |
| `BitDepth` | {class}`.ValueRange` |
| `get_bitdepth()` | {func}`.get_value_range` |
| `rescale(img, depth, bitdepth=...)` | `rescale(img, depth, value_range=...)` |

`BitDepth` conflated the encoding depth a value was decoded from with the value range
statistics are computed against. Separating them is what lets a range say "unknown", which
an integer depth cannot.

## Balance is corrected for chance

{class}`.Balance` values changed. All three of its DataFrames are now corrected for the
mutual information a factor's cardinality alone would produce, so a factor with many levels
no longer scores highly just for being fine-grained.

Expect different numbers and different rankings between factors of differing cardinality.
Factors of comparable cardinality rank as they did. See
[Dataset bias](../concepts/DatasetBias.md) for what the corrected values mean.

`Balance.num_neighbors` is deprecated and has no effect — every factor reaching the
estimator arrives already binned, which takes the discrete path where a neighborhood size is
never consulted.

A counting bug in `ClassBalance` was also fixed, which moves its results.

## Extractor changes

`ClassifierUncertaintyExtractor` is deprecated and removed in v1.2. Wrap a `TorchExtractor`
— or any {class}`.FeatureExtractor` — in {class}`.UncertaintyExtractor` for per-instance
uncertainty, or {class}`.ClasswiseUncertaintyExtractor` for per-class uncertainty.

Batching also became configurable: `TorchExtractor` and `OnnxExtractor` take a
`batch_size`, and {class}`.Embeddings` resolves its batch size from the extractor or the
global default rather than requiring one.

---

## One actual removal

`DuplicatesOutput["dataset_index"]` is gone. It was renamed to `dataset_indices` in v1.0
with a warning saying it would be removed in v1.1, and it was.

```python
result["dataset_index"]  # v1.0, warned
result["dataset_indices"]  # v1.1
```

## New in v1.1

These need no migration — they are additions.

| Feature | What it is |
| --- | --- |
| {class}`.Ontology` | Class-label alignment, validation and reconciliation against a declared label hierarchy, including equivalence concepts |
| Multi-object tracking | `Track` type, `build_tracks`, per-track statistics, and the `sequence` and `track` metadata levels |
| `Representation` and `Coverage` | Evaluators for label/ontology and embedding analysis |
| {class}`.DriftWasserstein` | Drift detector with a validation-calibrated baseline |
| `per_background=True` | Statistics measuring the scene behind an image's boxes |
| `channels=` | Named band groups on multispectral imagery |
| `Metadata.save` / `.load` | Cacheable serialization |

## Checklist

1. Pass `normalize_pixel_values` explicitly to `compute_stats`.
2. Declare `value_range=(low, high)` for float data outside `[0, 1]` and `0-255`.
3. Replace `per_channel=True` with a `channels={...}` mapping.
4. Add `level=` or `source_index=` to every `add_factors` call.
5. Replace deprecated `Metadata` members using the table above.
6. Move `dataeval.selection` and `dataeval.utils.data` imports to `dataeval.data`, and
   `Select` to `View`.
7. Replace `ClassifierUncertaintyExtractor`.
8. Rename `DuplicatesOutput["dataset_index"]` to `["dataset_indices"]`.
9. Run your pipeline and read the warnings — every deprecation names its replacement.
10. Recompute stored image statistics and `Balance` results before comparing them against
    fresh ones.
